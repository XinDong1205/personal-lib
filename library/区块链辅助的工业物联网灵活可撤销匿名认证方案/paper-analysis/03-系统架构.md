## 3.2 参与实体与角色

### 3.2.1 密钥生成中心（KGC）

| 维度 | 描述 |
|------|------|
| **信任假设** | 完全可信（fully trusted），不可被攻破 |
| **核心职责** | 系统初始化（生成主密钥 msk）、注册所有实体、颁发授权凭证 |
| **持有数据** | msk、所有设备的 lski、各服务的 (ωs, πs)、H1/H2 |
| **追溯能力** | 可追溯设备的真实身份 RID（通过 TI ⊕ H2(msk · TPK)） |
| **部署操作** | 向联盟区块链部署智能合约 |

### 3.2.2 智能设备（SD）

| 维度 | 描述 |
|------|------|
| **资源特性** | 计算能力有限、存储空间有限 |
| **存储数据** | {lski, ni, ωi, πi, RIDi, Ppub, P}，共 418 字节 |
| **签名能力** | 派生平密钥和匿名密钥，对每条消息进行签名 |
| **动态行为** | 可加入多个工业部门，参与多种服务，可主动离开 |

### 3.2.3 边缘服务器（ES）

| 维度 | 描述 |
|------|------|
| **资源特性** | 强大的计算和存储能力 |
| **双重角色** | (1) 某一工业部门的管理者 (2) 联盟区块链的成员节点 |
| **核心职责** | 审核 SD 的加入请求、派生匿名公钥并写入区块链、维护部门内 SD 的证书状态 |
| **持有数据** | {lskj, LPKj, asServs, Cs} |
| **追溯能力** | 可追溯 SD 的临时身份 TI |

### 3.2.4 联盟区块链（BC）

| 维度 | 描述 |
|------|------|
| **类型** | 联盟区块链（Consortium Blockchain），仅授权组织可访问 |
| **维护者** | 各 ES 共同维护 |
| **存储数据** | 临时证书（tc）和匿名证书（ac）及其有效性状态 |
| **安全特性** | 去中心化、透明性、防篡改 |
| **智能合约** | 预先部署，自动执行证书的写入、查询、撤销操作 |

## 3.3 模块划分与分工

```
方案功能模块
├── 1. 系统初始化模块 (KGC)
│   ├── 系统参数生成 (msk, Ppub, H1, H2)
│   ├── 授权种子生成 (ωs, πs, Cs)
│   └── 实体注册 (ES: lskj/LPKj; SD: lski, ni, ωi, πi)
│
├── 2. 临时身份派生模块 (SD 端 + KGC 端)
│   ├── SD 端: 自行派生 (TI^x_i, TPK^x_i, tsk^x_i)
│   └── KGC 端: 同步派生并写入临时证书 tc^x_i → BC
│
├── 3. 加入请求与验证模块 (SD ↔ ES)
│   ├── SD 生成: 授权凭证非交互式证明 + join 签名
│   └── ES 验证: 临时证书查询 + 凭证有效性验证
│
├── 4. 匿名密钥派生模块 (SD + ES 独立派生)
│   ├── ES 端: 派生 APK^y_i,a 和 ac^y_i,a → 写入 BC
│   └── SD 端: 派生 ask^y_i,a, PID^y_i,a, APK^y_i,a
│
├── 5. 消息签名与验证模块 (SD ↔ SD/BC)
│   ├── 签名方 SD: 生成 σi = vi + ask^y_i,a · fi
│   ├── 验证方 SD: 查询 BC 中匿名证书 → 验证等式
│   └── 批量验证: 小指数测试技术 (small exponent test)
│
└── 6. 追溯与撤销模块 (ES + BC + KGC 协同)
    ├── 匿名证书级撤销 (ES 操作)
    ├── 临时证书级撤销 (ES + BC)
    └── 真实身份级撤销 (KGC + ES + BC 协同)
```

## 3.5 安全/威胁模型

### 攻击者分类

```
攻击者
├── 外部攻击者 (External Adversary)
│   └── 不直接参与认证过程的 IIoT 实体
│       ├── 被动攻击: 窃听通信信道，分析数据以挖掘签名者真实身份
│       └── 主动攻击: 接入通信信道，截获/篡改/伪造/重放传输的数据包
│
└── 内部攻击者 (Internal Adversary)
    └── 参与认证过程的 IIoT 实体 (ES 或 SD)
        ├── 恶意 SD: 可能发送虚假数据、试图获取其他 SD 的身份
        └── 恶意 ES: 可能尝试超越权限追溯 SD 的真实身份
```

### 信任假设

- **KGC 完全可信**：KGC 持有主密钥 msk，负责所有实体的注册。论文明确声明 "the KGC is fully trusted and can not be compromised"。这是一个强假设。
- **ES 半可信（semi-trusted）**：ES 可以诚实执行协议，但不能被完全信任访问 SD 的真实身份。ES 持有 lskj 和协助验证参数 asServs，可追溯 SD 的临时身份 TI 但无法直接追溯到 RID。
- **BC 去中心化可信**：联盟区块链由多个 ES 共同维护，假设大多数 ES 诚实，因此 BC 上数据不可篡改。

### 安全目标

| 安全目标 | 形式化/技术手段 |
|----------|----------------|
| 消息完整性与认证 | EU-CMA 安全（ROM + ECDLP 归约），签名等式验证 |
| 消息匿名性 | 真实身份隐藏于 TI = RID ⊕ H2(tsk · Ppub)，依赖 ECDHP |
| 不可链接性 | 每个假名 PID 动态变化、不重复 |
| 身份可追溯 | 两级追溯：ES 追溯 TI、KGC 追溯 RID |
| 抗重放攻击 | 时间戳 freshness 检查 |
| 抗冒充攻击 | 哈希单向性 + 匿名密钥保密性 |
| 抗修改攻击 | 签名验证不通过则丢弃 |

### 形式化安全：EU-CMA 定义

论文在 4.1 节给出了方案签名的形式化安全定义（Existential Unforgeability Against Chosen Message Attacks）：

> 在 EU-CMA 安全模型中，如果不存在多项式时间攻击者 A 在时间 t 内能以优势 ϵ 赢得以下游戏（假设最多 qs 次签名查询），则签名方案是 $(t, q_s, \epsilon)$-安全的：

游戏过程：
1. C（挑战者）生成 (sk, pk) 并将 pk 发送给 A
2. A 自适应地选择消息并请求签名查询，C 返回对应签名
3. A 输出对一条新消息（未查询过签名的消息）的伪造签名

如果 A 输出的伪造签名通过验证，则 A 获胜；签名方案的安全性定义为 PPT 攻击者获胜的概率可忽略。
