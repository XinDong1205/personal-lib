## 3.2 参与实体与角色

### TA（Trust Authority，可信机构）

| 职责 | 描述 |
|------|------|
| 系统初始化 | 生成群公私钥对 `(gsk, gmpk)`，初始化累加器密钥 `(ask, apk)` |
| 车辆注册 | 为合法车辆生成 PS 签名凭证 `η` 和唯一标识 `uid` |
| 智能合约管理 | 部署认证合约和交易合约，是合约的 owner |
| 条件追溯 | 在发现恶意行为时，通过搜索本地注册表开放签名并提取车辆身份 |
| 恶意用户撤销 | 调用 `updateUser` 更新累加器值，将被撤销车辆从合法集合中移除 |
| 区块链维护 | 与其他节点共同维护区块链网络 |

**信任假设**：TA 被认为是完全可信的（trusted），拥有足够的计算和通信能力。但实际上论文也考虑了 TA 可能被攻破的情况（见 key escrow 分析）。

### Vehicle（车辆）

| 职责 | 描述 |
|------|------|
| 注册 | 生成私钥 `ski`、计算 PS 签名 `σ`、构造 ZKPOK1 证明，向 TA 注册 |
| 消息签名 | 对通信消息生成 SOK1（群签名 π）和加密伪名 `cnym` |
| 显式链接 | 当需要跨 scope 链接时，主动生成 ZKPOK2 证明并发送给 DP |
| Witness 维护 | 监听认证合约的链上更新，自行更新累加器 witness |

**关键私密信息**：`gski = (ski, η)`，其中 `ski` 是车辆的秘密值（连 TA 也不知道），`η` 是 TA 颁发的 PS 签名凭证。

### RSU（Roadside Unit，路侧单元）

| 职责 | 描述 |
|------|------|
| 消息验证 | 验证车辆发送的群签名 π 的有效性 |
| 数据上传 | 将认证信息 `(π, cnym)` 上传至区块链的交易合约 |
| 消息转发 | 将消息 m 转发给 DP 供分析 |
| 信息广播 | 向车辆广播路况、交通管理指令等 |

### Blockchain（区块链）

| 职责 | 描述 |
|------|------|
| 认证合约 | 存储车辆注册信息 `(uid, tag, acc)`，管理合法/撤销状态 |
| 交易合约 | 存储认证数据 `(π, cnym1, cnym2)`，按 `txid = H2(m)` 索引 |
| 数据完整性 | 保证已上链数据不可篡改 |

### DP（Data Processor，数据处理器）

| 职责 | 描述 |
|------|------|
| 伪名解密 | 用私钥 `dsk` 解密 `cnym` 获得伪名 `nym = H1(scp)^ski` |
| 隐式链接 | 比较同一 scope 下的伪名是否相等，从而关联同一车辆的数据 |
| 显式链接验证 | 验证车辆主动提交的 ZKPOK2 证明，确认不同 scope 的伪名属于同一车辆 |
| 数据分析 | 基于链接结果进行交通分析，向车辆或 RSU 提供指令 |

**关键限制**：DP 是 honest-but-curious 模型——正确执行协议但可能试图获取更多隐私信息。协议设计确保 DP 只能获得协议允许范围内的信息。

## 3.3 模块划分与分工

```
BAP 协议栈
├── 认证层（Authentication Layer）
│   ├── PS 群签名模块：证书颁发、签名随机化、群签名生成
│   ├── SOK 模块：知识签名（SOK1），将 ZKPOK 绑定到消息
│   └── 累加器模块：动态成员管理（注册/撤销）
│
├── 链接层（Linkability Layer）
│   ├── 伪名生成模块：nym = H1(scp)^ski
│   ├── 隐式链接模块：同 scope 伪名相等性检查
│   ├── 显式链接模块：ZKPOK2 跨 scope 链接证明
│   └── 加密伪名模块：ElGamal-like 加密 cnym = (g^α, dpk^α · H1(scp)^ski)
│
├── 区块链层（Blockchain Layer）
│   ├── 认证合约（Authentication Contract）：uid + tag + acc 管理
│   └── 交易合约（Transaction Contract）：π + cnym 存储
│
└── 追溯层（Traceability Layer）
    ├── 开放签名：TA 搜索本地注册表匹配 γ
    └── 撤销管理：累加器更新 + 合约状态变更
```

## 3.5 安全/威胁模型

### 攻击者能力假设

论文采用了密码学协议中标准的 PPT（Probabilistic Polynomial Time）攻击者模型：

- **计算能力**：攻击者是概率多项式时间的，即不能破解底层的密码学假设（ECDLP、双线性对的困难性）
- **网络能力**：攻击者可以窃听无线通信、注入消息、发起重放攻击和篡改攻击
- **随机预言机模型（ROM）**：安全性证明在随机预言机模型下进行（将哈希函数视为随机预言机）

### 信任边界

| 实体 | 信任假设 | 可访问的信息 |
|------|----------|-------------|
| TA | 完全可信（但论文考虑了 compromise 情况下的 key escrow 抗性） | 车辆注册信息 `(i, γ, γ̃, σ, uidi)`，但不知道 `ski` |
| DP | honest-but-curious | 伪名 `nym`，同 scope 内可链接；跨 scope 仅在车辆授权后可链接 |
| RSU | 不完全可信 | 接收群签名 π 和加密伪名 cnym，无法恢复车辆真实身份 |
| 其他车辆 | 不可信 | 仅接收签名消息，无法链接或识别发送者 |

### 安全目标（论文 Section III-B 列出的 8 项需求）

1. **消息认证（Message Authentication）**：接收方可验证消息来源合法且未被篡改
2. **隐私保护（Privacy Preservation）**：车辆身份被隐藏，仅 TA 在必要时可开放
3. **条件可追溯（Conditional Traceability）**：仅 TA 可追溯恶意车辆的真实身份
4. **不可链接性（Unlinkability）**：攻击者无法关联同一车辆的两条消息
5. **抗常见攻击**：重放攻击、篡改攻击、假冒攻击、中间人攻击、密钥托管问题、生日碰撞
6. **隐式可链接性（Implicit Linkability）**：DP 可自动关联同一 scope 下同一车辆的伪名
7. **显式可链接性（Explicit Linkability）**：车辆主动提供证明后，DP 可关联跨 scope 的数据
8. **用户可控（User-Controlled）**：跨 scope 链接由车辆主动控制，非强制

### 密码学假设

- **ECDLP 假设**：椭圆曲线离散对数问题难解（Soundness 证明依赖）
- **q-SDH / q-DHE 类假设**：PS 签名的不可伪造性依赖
- **随机预言机模型**：Fiat-Shamir 变换的安全性依赖（将 Σ-protocol 转为非交互式 SOK）
- **Type-3 双线性对**：G1 和 G2 之间不存在可高效计算的同态映射
