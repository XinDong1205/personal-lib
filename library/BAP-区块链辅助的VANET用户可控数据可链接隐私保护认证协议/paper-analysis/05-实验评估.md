# 5. 实验与评估

## 5.1 实验设计

论文从三个维度评估 BAP 的性能：

1. **区块链成本（Blockchain Cost）**：衡量智能合约部署和调用的 gas 消耗及对应的法币成本
2. **认证成本（Authentication Cost）**：衡量密码学原语的计算时间和签名/通信数据大小
3. **仿真成本（Simulation Cost）**：在模拟 VANET 环境中测量网络性能指标（APD、PLR）

这三个维度分别对应**经济可行性**、**计算可行性**和**网络可行性**，覆盖较为全面。

## 5.3 数据集/测试场景

论文**没有使用公开数据集**，而是使用合成场景（synthetic scenario）：

- **地图数据**：使用华盛顿特区真实地图的 1 km² 区域（论文 Fig. 12），以及一个虚拟地图（论文 Fig. 13）
- **移动模型**：通过 VanetMobiSim 生成车辆移动轨迹
- **网络拓扑**：通过 NS-2 设置车辆节点数、RSU 数量和通信链路延迟

**评价**：使用合成数据而非真实 VANET 数据集是一个明显的局限。真实 VANET 数据的流量模式、车辆密度分布、通信行为等与合成模型存在差异。

## 5.4 对比方案

论文选择两个最新的区块链辅助认证方案作为对比基线：

| 方案 | 发表信息 | 核心技术 | 与 BAP 的关系 |
|------|----------|----------|--------------|
| **BCPPA [4]** | IEEE TITS, 2021 | 区块链 + 密钥派生 + 有条件隐私保护 | 最直接的对比对象 |
| **BPAS [7]** | IEEE TII, 2020 | 区块链 + 模糊提取器 + 属性基加密 | 提供额外的访问控制 |

### 对比的公平性分析

1. **BCPPA** 是公平的对比对象：同属区块链辅助 VANET 认证协议，且时间较近（2021 vs 2024），安全目标类似
2. **BPAS** 的对比存在一些不对等：BPAS 额外支持基于属性的访问控制（ABE），因此其计算和通信开销天然更大。论文自己也承认了这一点（"Note that [7] provides additional access control, so the cost is larger"）
3. **共同缺失**：两个对比方案都不支持数据可链接性，因此 BAP 的额外开销可以归因于新增的链接性功能

### 缺失的对比

论文没有与以下类型的方案对比：
- 传统的非区块链群签名方案（如完全基于 PKI 的）
- 其他支持可链接性的群签名方案（如 Garms & Lehmann [9]、Diaz & Lehmann [10]）
- 更近期的区块链 VANET 方案（2022–2023 年间发表的）

## 5.5 实验结果分析

### 5.5.1 区块链 Gas 成本（Figs. 8 & 9）

| 操作 | Gas 消耗 | USD 成本 |
|------|----------|----------|
| deploy1（认证合约部署） | 较大（仅一次） | — |
| deploy2（交易合约部署） | 较大（仅一次） | — |
| updateUser | 154,426 | ≈ 0.00494 USD |
| addTx | 365,576 | ≈ 0.01170 USD |
| getAcc | 0（view 方法） | 0 |
| getTx | 0（view 方法） | 0 |

**分析**：

- **单次注册成本**（updateUser）约 0.5 美分，**单次消息上传成本**（addTx）约 1.2 美分。以 VANET 中每辆车每天发送数百条消息计算，如果每条消息都上链，日成本可达数美元，这在规模化部署时可能是一个显著问题。
- 但需要注意的是，**getAcc 和 getTx 是免费操作**（view 方法不修改链上状态），这意味着频繁的读取操作（如车辆获取最新 acc 值）不会产生 gas 成本。这是聪明的设计——将写操作（低频，如注册/撤销）和认证信息上传（中频）放在链上，读操作（高频）不消耗 gas。
- 部署成本虽然高，但仅发生一次，可被摊销。

### 5.5.2 可扩展性——TPS 测试（Figs. 6 & 7）

- 区块链的平均 TPS 在 **350–450** 范围内
- 即使在并发度增加的情况下，TPS 保持相对稳定

**分析**：

- 以太坊 Rinkeby 测试网的 350–450 TPS 对于 VANET 场景中大规模的实时认证消息而言**可能不足**。考虑一个中等城市可能有上万辆车同时通信，每秒产生数千条消息。
- 但论文的设计并不要求每条消息都上链：车辆直接通过无线通信（V2V/V2R）交换消息，只有 RSU/车辆将认证信息异步上传至区块链。这在一定程度上缓解了 TPS 瓶颈。
- 论文未讨论如果 TPS 不足时系统如何降级（如使用链下通道、批量上传等）。

### 5.5.3 认证计算成本（Table III & Fig. 10）

| 方案 | 签名生成 | 签名验证 |
|------|----------|----------|
| BCPPA [4] | 较低 | 较低 |
| BPAS [7] | **最高**（有 ABE 加密） | 较高 |
| BAP（本文） | 中等（预计算优化后） | 中等 |

**分析**：

- BAP 的计算成本介于 BCPPA 和 BPAS 之间，论文认为这是"可接受的范围"
- **预计算优化的有效性**：通过预计算 `U₁-U₄`（配对操作），在线签名时仅需要指数和乘法运算，大幅降低了时延。这是实用密码学中的常见技巧。
- 但论文未给出**具体的绝对时间数字**（毫秒），仅提供了每个操作的执行时间表格（Table II）。如果能提供端到端的签名延迟（如"从车辆决定签名到生成完整 SOK1 需要 X ms"），会更有说服力。

### 5.5.4 通信成本——签名大小（Fig. 11）

| 方案 | 签名/通信大小 |
|------|-------------|
| BCPPA [4] | 264 bytes + |msg| |
| BPAS [7] | 200 bytes + 128ℓ + |msg|（与属性数量 ℓ 线性相关） |
| BAP（本文） | **354 bytes** + |msg| |

**分析**：

- BAP 的签名大小为 354 bytes（包含 SOK1 证明 + 加密伪名），在提供额外功能（隐式/显式链接性）的前提下，这一尺寸是合理的
- 354 bytes 包含：`2|G₁| + 9|Zₚ| + |time| + |scp|`
- 相比传统 RSA 群签名（通常 KB 级），PS 签名（G₁ 元素仅 48 bytes，在 BLS12-381 上）确实带来了显著的尺寸优势
- 但 354 bytes 附加到每条 VANET 消息（通常也只有几百 bytes）上，意味着签名开销与消息本身相当甚至更大

### 5.5.5 仿真结果——网络性能

**实验 1：不同车辆密度下的 APD 和 PLR（Fig. 14）**

- 速度固定 30–40 m/s，延迟 0 ms
- 车辆密度从 5 增加到 100
- APD 在 30 辆车时开始上升，PLR 在 60 辆车时开始快速上升

**分析**：在 60 辆车/平方公里的密度下，网络开始出现拥塞。这个密度在真实城市环境中并不算高（高峰时段城市道路的车辆密度可能远超此值），表明方案在更高密度下的性能可能急剧下降。

**实验 2：不同速度下的 APD 和 PLR（Fig. 15）**

- 车辆数固定 50，延迟 0 ms
- 速度从 5 m/s 到 100 m/s
- APD 和 PLR 呈动态变化，不成线性关系

**分析**：速度对网络性能的影响不如密度显著，这与直觉一致——速度主要影响网络拓扑的变化频率，而非通信负载。

**实验 3：不同网络延迟下的 APD 和 PLR（Fig. 16）**

- 车辆数固定 50，速度 30–40 m/s
- 网络延迟从 10 ms 到 100 ms
- APD 和 PLR 随延迟增加呈正相关增长

**分析**：这是一个相对显然的结果。但论文同时设置了 0 ms 延迟的测试场景（实验 1 和 2），这与现实不完全相符——真实的 VANET 通信延迟很少为 0。

## 5.6 实验评价

### 实验的充分性

| 验证目标 | 是否验证 | 评价 |
|----------|----------|------|
| 区块链经济可行性 | ✓ | gas 和 USD 成本明确 |
| 区块链可扩展性 | 部分 | TPS 测试仅在本地/测试网，未在真实网络中验证 |
| 计算效率 | ✓ | 与两个方案对比，有预计算分析 |
| 通信效率 | ✓ | 签名大小对比清晰 |
| 网络性能 | 部分 | 仅使用仿真，无真实场景验证 |

### 实验的不足之处

1. **无真实部署**：所有测试都在模拟环境（Rinkeby 测试网、VanetMobiSim、NS-2）中进行，未在真实车辆或真实 VANET 环境中测试
2. **对比基线有限**：仅与 BCPPA 和 BPAS 两个方案对比，缺少与非区块链方案和其他支持链接性的方案的对比
3. **缺少端到端延迟数据**：未报告完整认证流程（从签名生成到验证完成）的端到端延迟
4. **安全级别不统一**：各方案可能基于不同的安全参数（如不同的椭圆曲线、不同的安全级别），但论文未对此进行归一化处理
5. **仿真参数覆盖面有限**：仅测试了单一地图区域和有限的参数组合
6. **缺少能耗评估**：对于 OBU 这类资源受限设备，能耗是一个关键指标，但论文未涉及
