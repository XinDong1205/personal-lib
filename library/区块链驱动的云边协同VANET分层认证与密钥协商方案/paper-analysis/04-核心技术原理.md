# 04 - 核心技术原理深度拆解

## 4.1 分层阈值秘密共享 (Hierarchical Threshold Secret Sharing)

**目的**：使 CS 和 ES 能够协作完成 AKA 请求的认证，同时体现两类服务器的差异化可信度——CS 拥有比 ES 更高的认证权重。

**核心思想**：为每个 CS 分配两个不同门限的 Shamir 秘密共享多项式（$t_1$ 门限和 $t_2$ 门限），为每个 ES 仅分配一个 $t_2$ 门限多项式。认证时要求总份额达 $t_2$ 且至少 $t_1$ 个来自 CS，从而实现了"一个来自高可信层的投票顶得上低可信层的投票，但低可信层单独投票也能构成总数"的层级认证逻辑。

**详细机制**：

1. **多项式生成**：
   - 每个 $CS_j$ 选取两个秘密值 $a_j, b_j \in \mathbb{Z}_q$，计算公钥 $U_j = a_j P$, $K_j = b_j P$
   - 基于 $a_j$ 生成多项式 $h_j(x)$（门限 $t_1$），基于 $b_j$ 生成多项式 $p_j(x)$（门限 $t_2$）
   - 每个 $ES_l$ 仅选取秘密值 $b_l$，生成多项式 $p_l(x)$（门限 $t_2$）
   - 多项式形式：$f_j(x) = u_j + a_{j,1}x + \cdots + a_{j,t-1}x^{t-1} \bmod q$

2. **秘密份额交换**：
   - 服务器间互相分发加密签名的秘密份额 $ss_{j,k} = (k, f_j(k))$
   - 每台服务器收到来自其他服务器的份额后，计算自己的**协作私钥**：
     - $CS_j$ 获得两个：$sk_{0,j} = \sum_{i=1}^{n_1} h_i(j)$（$t_1$ 门限）和 $sk_{1,j} = \sum_{i=1}^{n} p_i(j)$（$t_2$ 门限）
     - $ES_l$ 获得一个：$sk_{1,l} = \sum_{i=1}^{n} p_i(l)$（$t_2$ 门限）

3. **系统公钥**：$PK = \sum_{j=1}^{n} K_j + \sum_{j=1}^{n_1} U_j = K + U$

**创新点分析**：

- **传统方案**：$(t,n)$ 门限方案，所有份额持有者完全对等
- **本文方案**：双层门限 $(t_1, t_2)$，CS 拥有双重份额，自然体现差异化可信度
- 巧妙之处在于 CS 的两个秘密值 $a_j$ 和 $b_j$ **分别对应于不同门限**的多项式——$a_j$（$t_1$ 门限）贡献给 $U$，$b_j$（$t_2$ 门限）贡献给 $K$，这种分离设计使得系统公钥 $PK = U + K$ 对应了层级认证结构

**安全性分析**：
- 恢复系统私钥 $u = \sum a_j$ 需要至少 $t_1$ 个 CS 协作（Lagrange 插值）
- 恢复系统私钥 $k = \sum b_j$ 需要至少 $t_2$ 个服务器（CS+ES）协作
- 攻击者若只控制 ES，最多只能恢复 $k$ 部分而无法恢复 $u$ 部分，因为 ES 不持有 $h(x)$ 多项式份额

## 4.2 动态信誉评估机制

**目的**：在 AKA 流程开始前过滤低信誉车辆，降低内部攻击者参与认证会话的概率。

**核心思想**：利用周围车辆的实时反馈评估目标车辆消息的可信度，加权聚合后更新目标车辆的信誉值。高信誉车辆发送虚假消息会受到更严厉的惩罚，低信誉车辆累积信誉的速度受限。

**详细机制**：

### 4.2.1 反馈收集 (Feedback Collection)
- 接收车辆根据发送者的初始信誉值决定是否接受消息（黑名单车辆直接被拒绝）
- 接收方对消息 $m$ 给出可信度评分 $S_c \in [0,1]$
- 反馈信息 $M$ 包含：反馈车辆自身信息、消息 $m$、评分 $s_c$、时间戳

### 4.2.2 信誉计算 (Reputation Calculation)
- 将反馈车辆按信誉值分入三个区间组：$[60,75]$, $[75,90]$, $[90,100]$
- 每组分配评估权重 $w_1 < w_2 < w_3$（$\sum w_i = 1$）
- **加权可信度评分**：
  $$S_c = \frac{w_1}{n_1}\sum_{k=1}^{n_1} s_{1k} + \frac{w_2}{n_2}\sum_{k=1}^{n_2} s_{2k} + \frac{w_3}{n_3}\sum_{k=1}^{n_3} s_{3k}$$
- 若 $S_c > \beta$（阈值），奖励信誉；否则惩罚信誉

### 4.2.3 信誉更新 (Reputation Update)

**奖励函数**（$S_c > \beta$）：
$$Re_i = Re'_i + r_b \cdot \left(1 - \frac{Re'_i}{Re_{max}}\right) \cdot (\beta_1 \cdot D^{\beta_3} + \beta_2 \cdot S_c^{\beta_4})$$

**惩罚函数**（$S_c < \beta$）：
$$Re_i = Re'_i - r_b \cdot \left(\frac{Re'_i}{Re_{min}} - 1\right) \cdot (\beta_1 \cdot D^{\beta_3} + \beta_2 \cdot (1 - S_c)^{\beta_4})$$

**数学模型**（无偏性分析）：

1. **权重分配无偏性**：论文证明了当各组内评分独立同分布时，$E[S_c] = \mu$（底层真实均值），权重设计不会引入系统性偏差
2. **区间分组无偏性**：考虑所有可能的车辆分布情况（全部在 $G_1$、$G_2$ 或 $G_3$），分组机制保持无偏
3. **奖励/惩罚函数稳定性**：通过 Brouwer 不动点定理证明奖励函数在 $[Re_{min}, Re_{max}]$ 上收敛到一个不动点 $Re^*$，偏导 $\frac{\partial f_{reward}}{\partial Re_i} = 1 - \frac{r_b \cdot g(D,S_c)}{Re_{max}} \in (0,1)$ 保证了收缩性（contraction）

**创新点分析**：
- 两项约束因子 $(1 - Re'_i/Re_{max})$ 和 $(Re'_i/Re_{min} - 1)$ 实现了**抗马太效应**——高信誉车辆涨得慢、跌得快，低信誉车辆反之
- 引入了**车辆密度 $D$** 作为信誉评估的环境参数，高密度环境下反馈更可信
- 三个无偏性证明赋予了该启发式公式以理论基础，这在工程类信誉方案中较为少见

## 4.3 基于 Schnorr 变体的签名与验证

**目的**：车辆生成用于 AKA 请求的可验证签名，证明其拥有注册私钥 $x_i$。

**核心思想**：采用类似 Schnorr 签名的高效构造，用椭圆曲线标量乘法替代传统 Schnorr 的模指数运算。

### 签名生成
$$\epsilon_i = q_i + x_i \cdot h(addr_i, Q_i, t_i, X_i)$$
其中 $q_i$ 为临时随机数，$Q_i = q_i P$，$x_i$ 为车辆私钥，$X_i = x_i P$ 为公钥。

### 签名验证
$$\epsilon_i \cdot P \stackrel{?}{=} Q_i + h(addr_i, Q_i, t_i, X_i) \cdot X_i$$

这本质上是 Schnorr 签名的标准形式：若 $\epsilon_i = q_i + h \cdot x_i$，则 $\epsilon_i P = q_i P + h \cdot x_i P = Q_i + h \cdot X_i$。

## 4.4 分层 Token 生成与聚合

**目的**：让 CS 和 ES 各自使用其协作私钥，为认证通过的 AKA 请求生成可聚合的签名份额（Token）。

**核心思想**：每个服务器生成的签名份额本质上是一个**对同一消息的部分 Schnorr 签名**，利用了 Shamir 秘密共享的加法同态性质——多个 Lagrange 插值恢复的门限签名份额可以聚合为完整的系统签名。

### Token 生成公式
$$\sigma_j = r_j + \left(sk_j \cdot \prod_{1 \leq k \leq t, k \neq j} \frac{0 - x_k}{x_j - x_k}\right) \cdot h(addr_i, addr_k, PK, h(TX_k))$$

关键点解析：
- $sk_j$ 是服务器的协作私钥（$sk_{0,j}$ 或 $sk_{1,j}$）
- $\prod \frac{0 - x_k}{x_j - x_k}$ 是 Lagrange 基多项式在点 $0$ 处的取值（即 $L_j(0)$），这是 Shamir 秘密恢复的关键系数
- $r_j$ 是随机数，$R_j = r_j P$，用于保证每次生成的 Token 不同（防止重放）
- $tag$ 标签区分来自 CS 的双重份额（$tag = 0$）和单重份额（$tag = 1$）

### 为什么这样设计？

当聚合 $t$ 个这样的份额时（以 $t_1$ 门限为例）：

$$\sum_{j=1}^{t_1} \sigma_j^0 = \sum_{j=1}^{t_1} r_j^0 + \sum_{j=1}^{t_1} \left(sk_{0,j} \cdot L_j(0)\right) \cdot h(\cdots)$$

由于 $\sum sk_{0,j} \cdot L_j(0)$ 正是 Lagrange 插值恢复的秘密 $\sum a_j = u$（根据 Shamir 方案的正确性），所以：

$$\sum \sigma_j^0 = \sum r_j^0 + u \cdot h(\cdots)$$

同理，$t_2$ 个份额聚合恢复 $u + k$。这使得验证方程式 (16) 成立。

## 4.5 会话密钥协商

**目的**：在认证通过后，车辆和 RSU 安全地协商共享会话密钥。

**核心思想**：采用基于 ECDH 的密钥交换，双方各自用临时私钥乘以对方的临时公钥。

### 会话密钥构造
$$sk_{ik} = h(q_i \cdot Q_k, h(TX_k)) = h(q_k \cdot Q_i, h(TX_k))$$

**安全性保证**：
- $q_i \cdot Q_k = q_i \cdot (q_k P) = (q_i \cdot q_k) P = q_k \cdot (q_i P) = q_k \cdot Q_i$
- 基于 ECDHP：给定 $Q_i = q_i P$ 和 $Q_k = q_k P$，敌手无法计算 $q_i q_k P$
- $h(TX_k)$ 作为辅助输入绑定会话上下文，防止跨会话密钥混淆
- 临时密钥 $q_i, q_k$ 每次会话随机生成，天然保证前向安全性

## 4.6 形式化安全证明结构

**目的**：证明协议满足**会话密钥语义安全**（Session Key Semantic Security）。

**核心思想**：通过**Game Hopping**（游戏跳跃）技术，逐步修改挑战者行为，将敌手区分真实密钥和随机数的能力归约到破解 ECDDHP 或签名方案的难度。

### 游戏序列

```
Game 0 ──(hash oracle 模拟)──▶ Game 1 ──(Schnorr/ECDSA 归约)──▶ Game 2 ──(ECDDHP 归约)──▶ Game 3
  │                                │                                │                           │
  └─ 真实协议执行                   └─ hash 视为随机预言机            └─ 模拟被控服务器的行为      └─ DH 元组替换为随机
```

### 归约链（Reduction Chain）

1. **Game 0 → Game 1**：引入随机预言机模拟 hash 函数。由于 hash 输出的随机性，两个游戏不可区分
   $$Pr(W_1) = Pr(W_0)$$

2. **Game 1 → Game 2**：构建 Schnorr/ECDSA 的伪造者 $F$，利用敌手 $A$ 区分真实/模拟视图的能力来伪造签名。归约损失由文献 [24][25] 的结果限制：
   $$|Pr(W_2) - Pr(W_1)| \leq \epsilon_1 + \epsilon_2$$
   其中 $\epsilon_1 \leq \frac{3q_s(q_s+q_h)}{(q-1)/2 - q_s - q_h} + \frac{(q_s+q_h)^2}{2q} + q_h \epsilon$（ECDSA 不可伪造优势），$\epsilon_2 \leq \sqrt{\frac{q + 2q_s(q_s+q_h) + q(q_s+q_h)\epsilon}{q}}$（Schnorr 不可伪造优势）

3. **Game 2 → Game 3**：在 `Send` 预言机中，用 ECDDHP 挑战元组 $(A, B, C)$ 替换真实的 $Q_i, Q_k, Q_{ik}$。区分的优势直接等于破解 ECDDHP 的优势：
   $$|Pr(W_3) - Pr(W_2)| \leq q_s \cdot \epsilon^*$$

4. **Game 3 终态**：在 Game 3 中，会话密钥 $sk_{ik}$ 已被替换为与随机数不可区分，敌手只能通过猜中 hash 值来区分（概率 ≤ $q_h/q$）：
   $$|Pr(W_3)| \leq \frac{1}{2} + \frac{q_h}{q}$$

### 最终安全界
$$Adv_A \leq \frac{6q_s(q_s+q_h)}{(q-1)/2 - q_s - q_h} + \frac{2(q_s+q_h)^2}{2q} + 2q_h\epsilon + 2\sqrt{\frac{q + 2q_s(q_s+q_h) + q(q_s+q_h)\epsilon}{q}} + 2q_s \cdot \epsilon^* + \frac{2q_h}{q}$$

该上界表明，对于任意 PPT 敌手，在 ECDDHP 困难假设下，$Adv_A$ 是可忽略的，因此协议满足会话密钥语义安全。
