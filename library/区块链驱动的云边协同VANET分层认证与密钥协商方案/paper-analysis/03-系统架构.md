## 3.2 参与实体与角色

| 实体 | 数量 | 可信度 | 主要职责 |
|------|------|--------|---------|
| **系统发起者** (System Initiator) | 1 | 完全可信 | 生成系统安全参数、选择参与实体、管理区块链网络。**完成初始化后离线，不参与日常运行** |
| **云服务器** (CS) | $n_1$ | 半可信 (semi-trusted) | 构建联盟区块链、提供车辆/RSU 注册、参与 AKA 请求认证、生成签名份额 (Token) |
| **边缘服务器** (ES) | $n_2$ | 半可信 (semi-trusted) | 参与 AKA 请求认证、生成签名份额、**负责信誉值计算和更新** |
| **路侧单元** (RSU) | 多个 | — | 为车辆提供网络接入、转发 AKA 请求到区块链、参与会话密钥协商 |
| **车辆** (Vehicle) | 大量 | 不信任 | 发起 AKA 请求、参与会话密钥协商、具有动态信誉值 |

**关键设计**：$n_1 + n_2 = n$，系统总认证实体数为 $n$。设两个阈值 $t_1 < t_2$，要求：
- 总认证份额 ≥ $t_2$ 个
- 其中至少 $t_1$ 个来自 CS

### 智能合约模块（6 个 Algorithm）

| Algorithm | 功能 | 调用者 |
|-----------|------|--------|
| **Algorithm 1** | ES/CS 注册函数 | RA（注册机构） |
| **Algorithm 2** | Vehicle/RSU 注册函数 | CS |
| **Algorithm 3** | 公钥注册函数（Cuckoo Filter） | 已注册实体 |
| **Algorithm 4** | 公钥验证函数（Cuckoo Filter 查找） | 认证服务器 |
| **Algorithm 5** | Token 聚合函数（按 tag 分类存储） | CS/ES |
| **Algorithm 6** | Token 验证函数（阈值检查） | 任意实体 |

### 步骤详解

| 步骤 | 执行者 | 操作 | 输入 | 输出 |
|------|--------|------|------|------|
| ① | Vehicle | 生成密钥对 + Schnorr 签名 | 随机数 $q_i$, 私钥 $x_i$ | $M_i = \{addr_i, t_i, Q_i, X_i, \epsilon_i\}$ |
| ② | RSU | 验证 + 生成 ECDSA 签名交易 | $M_i$, 随机数 $q_k$ | $TX_k$ 发往区块链 |
| ③ | CS/ES | 四重验证 | $TX_k$ | 通过/拒绝 |
| ④ | CS/ES | 生成签名份额 (Token) | 协作私钥 $sk_{0,j}, sk_{1,j}$ | $\{h(TX_k), (\sigma_j, R_j, tag)\}$ |
| ⑤ | 区块链 | 聚合 + 阈值检查 | Token 集合 | 若达阈值，输出全部 Token |
| ⑥ | RSU/Vehicle | 提取 Token | 区块链查询 | $\{(\sigma_j, R_j, tag)\}$ 集合 |
| ⑦⑧ | Vehicle+RSU | 验证 + 计算会话密钥 | Token 集合, $q_i, q_k$ | $sk_{ik}$ |

## 3.5 安全/威胁模型

### 攻击者能力假设

论文采用标准的 PPT（概率多项式时间）敌手模型：

| 攻击类型 | 对应 Oracle | 攻击者能力 |
|---------|-------------|-----------|
| **被动攻击** | `Execute(Π_V, Π_RSU)` | 窃听 V 和 RSU 之间传输的所有消息 |
| **主动攻击** | `Send(Π_Λ, m)` | 发送任意消息给协议参与者，接收响应 |
| **前向安全攻击** | `Reveal(Π_V, Π_RSU)` | 获取指定会话的会话密钥 |
| **长期密钥泄露** | `Corrupt(Π_Λ)` | 获取实体的长期私钥（区块链地址私钥） |
| **会话密钥区分** | `Test(Π_V, Π_RSU)` | 挑战者随机选择真实密钥或随机数，敌手需区分 |

### 信任边界

```
  ┌──────────────────── 信任域 ────────────────────┐
  │                                                 │
  │  系统发起者 (完全可信，仅初始化时存在)              │
  │   ─ ─ ─ ─ ─ ─ 信任边界 ─ ─ ─ ─ ─ ─ ─          │
  │                                                 │
  │  CS 群 (半可信，可能被攻破 ≤ t₁-1 个)            │
  │  ES 群 (半可信，可能被攻破 ≤ t₂-t₁-1 个)         │
  │   ─ ─ ─ ─ ─ ─ 信任边界 ─ ─ ─ ─ ─ ─ ─          │
  │                                                 │
  │  RSU (不信任，需验证签名)                         │
  │  车辆 (不信任，需信誉 + 签名验证)                  │
  │  通信信道 (完全不信任，开放无线信道)               │
  └─────────────────────────────────────────────────┘
```

### 安全目标

1. **会话密钥语义安全**：PPT 敌手无法区分真实会话密钥和随机数（形式化定义为 $Adv(A) = 2|Pr(W) - 1/2|$ 可忽略）
2. **抗共谋攻击**：敌手需要同时攻破足够数量的 CS 和 ES 才能伪造认证
3. **前向安全性**：长期密钥泄露不影响历史会话密钥（由 ECDH 临时密钥保证）
4. **条件隐私保护**：车辆使用伪身份（区块链地址）通信，仅在恶意行为时由可信实体揭示真实身份

### 核心假设

- **ECDLP 困难假设**：椭圆曲线离散对数问题在多项式时间内不可解
- **ECDDHP 困难假设**：椭圆曲线判定性 Diffie-Hellman 问题在多项式时间内不可解
- **Schnorr 签名不可伪造**：在随机预言机模型下
- **ECDSA 签名不可伪造**：在随机预言机模型下
- **PBFT 共识安全**：拜占庭节点数 $< \frac{n}{3}$
