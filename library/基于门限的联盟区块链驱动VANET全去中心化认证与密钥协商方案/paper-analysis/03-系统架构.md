## 3.2 参与实体与角色

### 系统初始化器 (System Initiator)

- **信任假设**：全可信（但仅在系统初始化阶段在线，不参与日常 AKA 流程）
- **职责**：
  - 选择系统安全参数（椭圆曲线 $E$、生成元 $P$、群阶 $q$、门限值 $t$）
  - 选择具有认证特权的 ES 集合（数量 $n$）
  - 管理区块链网络的初始配置
  - 将 ES 和 RSU 的区块链地址写入智能合约（在合约部署前）
- **离线特性**：这是本文设计的一个关键点——系统初始化器是**一次性存在**的，完成初始化后不再参与系统运行。这意味着日常 VANET 运行中没有任何全可信实体在线。

### 边缘服务器 ES (Edge Server)

- **信任假设**：半可信（semi-trusted）——既不是完全不可信，也不是全可信
- **编号**：ESⱼ，其中 $j = 1, 2, ..., n$，每个 ES 有唯一索引 $j$
- **私钥**：$u_j$（用于分布式认证）、$e_j$（用于安全传输）
- **公钥**：$U_j = u_jP$、$E_j = e_jP$
- **职责**：
  - **注册服务**：就近为车辆提供身份注册
  - **认证服务**：验证车辆的 AKA 请求是否合法（消息签名验证 + 行为分析）
  - **Token 生成**：对合法的 AKA 请求生成分布式认证 Token（部分签名）
  - **行为分析**：结合附近 RSU 的历史通信数据判断车辆是否恶意
  - **密钥撤销**：在密钥协商结束后执行公钥撤销操作
- **关键约束**：被攻陷的 ES 数量**不超过门限 $t$**

### 路侧单元 RSU (Roadside Unit)

- **信任假设**：半可信
- **私钥**：$s_k$（用于签署区块链交易）
- **职责**：
  - **网络接入**：为车辆提供 VANET 网络连接服务
  - **消息转发**：接收车辆 AKA 请求，生成 ECDSA 签名交易 $TX_k$ 转发至联盟区块链
  - **异常检测**：部署有基于机器学习的异常检测机制，根据历史通信行为判断车辆是否恶意
  - **时间戳验证**：检查 AKA 请求消息的新鲜度（$|t_i - t_{cur}| \leq \Delta T$）

### 车辆 (Vehicle)

- **信任假设**：不可信（untrusted）——车辆可能是恶意内部攻击者
- **私钥/公钥**：
  - 区块链地址私钥 $e_i$ → 地址 $addr_i$
  - AKA 签名私钥 $x_i$ → 公钥 $X_i = x_iP$（可生成列表 $pks_i$ 批量注册）
  - 临时密钥协商私钥 $q_i$ → 公钥 $Q_i = q_iP$（每次 AKA 随机生成）
- **职责**：
  - 向附近 ES 注册身份
  - 在区块链上注册公钥（通过智能合约）
  - 发起 AKA 请求（生成签名 $\epsilon_i$）
  - 验证认证结果（收集 $t$ 个 Token 后验证）
  - 计算会话密钥 $sk_{ik}$

## 3.3 模块划分与分工

### 模块 1：区块链基础设施层

- **联盟区块链**：由 RSU 和 ES 共同维护，作为分布式共享数据库
- **创世区块**：存储公开参数 $\{E, G, q, P, n, U_j, E_j\}$（$1 \leq j \leq n$）
- **智能合约集**：
  - `Algorithm 1` — 车辆注册函数：仅在 ES 调用时有效，将车辆地址标记为合法
  - `Algorithm 2` — 公钥注册函数：将车辆公钥指纹插入 Cuckoo Filter
  - `Algorithm 3` — 公钥验证函数：查询 Cuckoo Filter 确认公钥合法性
  - `Algorithm 4` — Token 聚合函数：收集各 ES 提交的部分签名
  - `Algorithm 5` — Token 验证函数：检查是否达到门限，返回所有 Token
  - `Algorithm 6` — 公钥撤销函数：从 Cuckoo Filter 中删除公钥指纹

### 模块 2：秘密共享与门限密码学层

- **秘密分片生成**：每个 ESⱼ 生成自己的 $(t-1)$ 阶多项式 $p_j(x)$
- **分片安全分发**：通过 ECIES+ECDSA 加密签名通道交换分片
- **合作私钥推导**：每个 ESⱼ 计算 $sk_j = \sum_{k=1}^{n} p_k(j)$
- **系统公钥聚合**：$PK = \sum_{j=1}^{n} U_j$，用于 Token 聚合验证

### 模块 3：消息认证与 Token 生成层

- **签名验证**：$\epsilon_i \cdot P \stackrel{?}{=} Q_i + h(addr_i, Q_i, t_i, X_i) \cdot X_i$
- **Token 生成**（部分签名）：$\sigma_j = r_j + sk_j \cdot \prod_{k \neq j} \frac{0 - x_k}{x_j - x_k} \cdot h(M)$
- **Token 聚合验证**：$\sum_{j=1}^{t} \sigma_j \cdot P \stackrel{?}{=} \sum_{j=1}^{t} R_j + h(M) \cdot PK$

### 模块 4：密钥协商层

- **ECDH 密钥交换**：$sk_{ik} = h(q_i \cdot Q_k, h(TX_k)) = h(q_k \cdot Q_i, h(TX_k))$
- **会话密钥派生**：使用密钥派生函数（KDF）从 $sk_{ik}$ 生成一系列短期会话密钥

## 3.5 安全/威胁模型

### 攻击者能力假设

1. **半可信的内部实体**：联盟区块链内的所有节点（ES、RSU）被认为是半可信的。它们会诚实地执行协议，但可能出于好奇或被收买而尝试获取额外信息。被攻陷的 ES 数量不超过门限 $t$。

2. **通信信道假设**：所有无线通信信道是开放且不安全的。攻击者可以：
   - 窃听（eavesdrop）：被动监听所有无线通信内容
   - 篡改（modify）：修改传输中的消息
   - 伪造（fabricate）：伪造通信内容
   - 重放（replay）：重放过期消息

3. **攻击者分类**：
   - **外部攻击者**：未注册的外部敌手，可以探测信道、尝试获取/修改/伪造通信内容
   - **内部攻击者**：已注册的合法节点，可能发起合谋攻击以获取秘密信息

### 信任边界

```
                  Trusted Zone (无)
                       │
  ┌────────────────────┼────────────────────┐
  │                    │                    │
  ▼                    ▼                    ▼
Semi-Trusted       Semi-Trusted        Untrusted
   ESs               RSUs              Vehicles
   (t-of-n)          (anomaly           (may be
                     detection)         malicious)
```

**关键设计原则**：
- 系统初始化器虽然可信，但在初始化完成后永久离线——这是一个重要的安全边界
- ES 从"全可信"降级为"半可信"，通过门限机制（$t$-of-$n$）来容忍部分 ES 妥协
- 车辆被假设为完全不可信——是最保守、最严格的安全假设

### 安全目标

论文列出了 10 项具体安全需求：
1. **双向认证**（Mutual Authentication）
2. **机密性**（Confidentiality）
3. **抗重放攻击**（Resistance to Replay Attacks）
4. **抗中间人攻击**（Resistance to MITM Attacks）
5. **抗 DDoS 攻击**（Resistance to DDoS Attacks）
6. **抗合谋攻击**（Resistance to Collusion Attacks）
7. **抗密钥暴露攻击**（Resistance to Key Exposure Attacks）——**核心创新点**
8. **前向和后向安全**（Forward and Backward Secrecy）
9. **完美前向安全**（Perfect Forward Security）
10. **条件隐私保护**（Conditional Privacy-Preserving）
