# 07 - 未来研究方向

## 7.1 论文提出的未来工作

论文本身**未在正文中设专门的"Future Work"章节**。结论部分（Section VII）主要是对已完成工作的总结，未明确展望未来方向。然而，从论文的方案设计和实验分析中，可以推断出以下几个论文隐含指向但未解决的方向：

1. **行为分析的密码学化**：论文的 ES 行为分析模块（判断车辆是否恶意）完全依赖非密码学方法（如 ML 异常检测）。如何将行为评估以密码学方式绑定到认证流程中，是一个论文未触及但重要的方向。

2. **动态门限调整**：当前方案的门限 $t$ 在系统初始化时固定。论文提到了 "$t$ 的具体值取决于系统鲁棒性和性能之间的平衡"，暗示未来可能研究自适应或动态的 $t$ 选择机制。

3. **跨域/跨链互操作**：当前方案假设单一联盟区块链。在多域 VANET（如不同城市、不同运营商）场景中，如何实现跨链的互操作认证是一个自然延伸。

## 7.2 潜在的扩展方向

### 方向 1：可验证的行为评估（Verifiable Behavior Assessment）

**问题**：当前 ES 的车辆行为分析是黑盒的、不可外部验证的。

**改进思路**：
- 使用可信执行环境（TEE，如 Intel SGX）在 ES 上运行行为分析模型，通过远程证明（remote attestation）让车辆/RSU 验证 ES 确实执行了正确的模型
- 使用零知识证明（ZKP，如 zk-SNARK）证明"对某车辆的历史通信数据分析结果满足某种安全属性"，而无需暴露 ES 使用的具体模型或数据
- 集成基于信誉（reputation）的链上机制：让车辆的通信行为评分上链，结合门限投票决定是否撤销其认证资格

### 方向 2：动态门限与自适应安全策略

**问题**：安全威胁级别是动态变化的（如网络攻击增多时需提高 t，正常运营时可降低 t 以减少延迟）。

**改进思路**：
- 设计基于当前网络安全状态的动态 t 调整协议（t = f(网络攻击检测事件频率, 车辆密度, 时间段)）
- 利用联盟链的共识机制实现 t 的分布式更新：当一定数量 ES 通过共识认为需要调整 t 时，通过智能合约自动更新参数
- 分层门限（Hierarchical Threshold）：为不同安全级别的 AKA 请求设置不同的 t 值（如普通消息 t=5，紧急消息 t=10）

### 方向 3：Cuckoo Filter 假阳性风险的显式管理

**问题**：当前的 Cuckoo Filter 设计未量化或控制假阳性概率。

**改进思路**：
- 根据预期车辆注册数、单次 AKA 存续周期、可接受的假阳性概率上限，形式化推导 Cuckoo Filter 的参数（bucket 数、fingerprint 长度、每 bucket slot 数）
- 当 Filter 负载因子（load factor）超过阈值时，通过智能合约自动触发扩容操作（创建新的更大 Filter 并迁移数据）
- 考虑使用更先进的概率数据结构（如 XOR Filter，比 Cuckoo Filter 更节省空间），但需评估其对删除操作的支持

### 方向 4：更完整的区块链层安全分析

**问题**：当前安全模型忽略了区块链共识层攻击。

**改进思路**：
- 分析联盟链共识协议（如 PBFT、Raft）的特性对 AKA 方案安全性的影响
- 考虑交易重新排序攻击：攻击者能否通过操控交易顺序来干扰 Token 聚合结果？
- 分析链上信息泄露：Token 提交交易中是否包含可链接到特定车辆的元数据（如 Gas 价格模式）？

### 方向 5：将方案思想迁移到其他领域

本方案的核心思想——"用门限机制替代单点信任 + 用概率数据结构降低链上成本 + 用轻量级密码学提高端侧性能"——可以迁移到：

1. **无人机网络（UAV Networks）**：类似 VANET 的高移动性、开放信道、对等通信场景
2. **IoT 设备认证**：大量 IoT 设备的身份认证面临与 VANET 类似的中心化风险和链上成本问题
3. **去中心化数字身份（DID）**：将门限认证思想与 W3C 的 DID 标准结合，构建无单点信任的数字身份系统
4. **5G/6G 网络切片认证**：网络切片场景中需要高效的跨切片认证，门限机制可以分散信任到多个切片管理实体

### 方向 6：与 V2X 标准化的对齐

论文引用了 T/CSAE 53-2020（中国汽车工程学会的 V2X 通信标准）来验证延迟达标，但方案使用的是 IEEE 802.11p（DSRC 族），而最新的 V2X 标准正向 C-V2X（Cellular V2X，如 3GPP NR-V2X）演进。未来工作需要：

- 评估方案在 C-V2X 下的适应性（C-V2X 具有不同的延迟和可靠性特征）
- 考虑与 3GPP 5G-AKA 标准的兼容性
- 分析在 5G/NR 安全架构下，本方案的门限 ES 如何与 5G 核心网的 AUSF/UDM 互操作

## 7.3 相关工作延伸阅读

基于该论文的研究脉络，以下 5 篇（组）工作可以作为延伸阅读：

### 1. Threshold ECDSA 与去中心化签名

**推荐文献**：Gennaro, R., & Goldfeder, S. (2018). "Fast Multiparty Threshold ECDSA with Fast Trustless Setup." *ACM CCS 2018*.

**为什么相关**：本方案的 Token 生成本质是门限 Schnorr 签名（加法同态使门限化更简单）。若未来需要使用 ECDSA 兼容签名（而非 Schnorr），则需要更复杂的 MPC 协议（涉及 $k^{-1}$ 的秘密共享），Gennaro & Goldfeder 的方案是这方面的标杆。

### 2. 区块链 VANET 安全的最新进展

**推荐文献**：Lin, C., Huang, X., & He, D. (2023). "EBCPA: Efficient Blockchain-based Conditional Privacy-Preserving Authentication for VANETs." *IEEE TDSC*.

**为什么相关**：被本文引用 [16]，是同期在 VANET + 区块链 + 隐私保护方向上具有代表性的工作，可以与本文形成互补阅读——EBCPA 侧重条件隐私保护，本文侧重全去中心化架构。

### 3. 概率数据结构在安全协议中的应用

**推荐文献**：Fan, B., Andersen, D. G., Kaminsky, M., & Mitzenmacher, M. D. (2014). "Cuckoo Filter: Practically Better than Bloom." *ACM CoNEXT 2014*.

**为什么相关**：这是 Cuckoo Filter 的原始论文 [25]，理解 Cuckoo Filter 的设计细节（特别是假阳性率的精确计算和控制方法）对于评估本方案链上存储部分的实际安全性至关重要。同时可以对比更新的过滤器设计（如 Vacuum Filter、Morton Filter）。

### 4. VANET 中的去中心化认证架构

**推荐文献**：Yang, A., Weng, J., Yang, K., Huang, C., & Shen, X. (2022). "Delegating Authentication to Edge: A Decentralized Authentication Architecture for Vehicular Networks." *IEEE TITS*.

**为什么相关**：这是本文最直接的对比方案 [28]，也使用门限机制和边缘节点进行认证委托。与本方案的核心区别在于 Yang 的方案仍使用双线性对和 IBC。对比阅读有助于理解"为什么本方案选择放弃双线性对"这一关键设计决策的 trade-off。

### 5. 形式化验证在安全协议中的应用

**推荐文献**：Kobeissi, N., Nicolas, G., & Tiwari, M. (2020). "Verifpal: Cryptographic Protocol Analysis for the Real World." *INDOCRYPT 2020*.

**为什么相关**：本文使用 Verifpal 作为协议验证工具。Verifpal 的设计哲学是"对真实世界的实用形式化分析"而非完全自动化的安全证明。了解 Verifpal 的能力边界（它能验证什么、不能验证什么）有助于正确理解本文 Section V-F 工具验证结果的含义。
