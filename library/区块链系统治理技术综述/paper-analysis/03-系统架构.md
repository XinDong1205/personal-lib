## 3.5 安全/威胁模型

### 论文识别的安全威胁维度

论文在分析链上治理投票的七个属性时，隐含了一个安全威胁模型：

```
                        攻击面 (Attack Surface)
 ┌──────────────────────────────────────────────────────────────┐
 │                                                              │
 │  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐    │
 │  │ 身份伪造  │  │ 胁迫投票  │  │ 女巫攻击  │  │ 51%攻击  │    │
 │  │(Sybil)   │  │(Coercion)│  │(Collusion)│  │(Majority)│    │
 │  └──────────┘  └──────────┘  └──────────┘  └──────────┘    │
 │                                                              │
 │  攻击者能力假设:                                               │
 │  • 攻击者可以注册多个虚拟地址（需要 Authentication 防御）        │
 │  • 攻击者可以贿赂或胁迫投票者（需要 Coercion-freeness 防御）     │
 │  • 攻击者可以通过勾结操纵投票（需要 Quadratic Voting 防御）      │
 │  • 攻击者可能控制大量代币或算力（需要 Token-lock 防御）          │
 │                                                              │
 └──────────────────────────────────────────────────────────────┘
```

### MULTAV 的安全性分析（论文原文的批评）

论文对 MULTAV [34] 的安全分析提出了批评：

- **原文声称**：若每个链 $CS_i, i=1,...,m$ 被攻破的概率为 $p$，则整个系统被攻破的概率为 $p^m$
- **论文指出**：当投票结果接近通过阈值时（如 70%），任一链被攻破影响 1% 的选票即可改变最终结果。因此实际攻破概率为 $p$，而非 $p^m$
- **论文结论**：MULTAV 原文的安全性分析**不合理（not reasonable）**

这是本文最具批判性技术深度的部分，体现了综述论文的独立判断力。

### 各治理范式的信任假设

| 治理类型 | 信任假设 | 主要威胁 |
|---------|---------|---------|
| 链下治理 | 信任核心开发者和专家的判断力 | 精英捕获（Elite Capture）、激励不对称 |
| 链上治理（代理投票） | 信任代理人专业且诚实 | 代理人集权、可问责性缺失 |
| 链上治理（二次方投票） | 信任成本机制能遏制寡头 | 超级富豪无视成本、勾结 |
| 链上治理（跨链投票） | 信任所选择的成熟链安全 | 跨链合约漏洞、高 Gas 成本 |
| 链上治理（代币锁定投票） | 信任经济惩罚有效 | 通缩压力、惩罚时机窗口 |
| 混合治理 | 信任链上/链下的合理分工 | 边界模糊、技术不成熟 |
