# 3. 整体架构与系统设计

## 3.2 参与实体与角色

| 实体 | 身份 | 职责 | 信任假设 |
|------|------|------|----------|
| **User（用户）** | 任务发起方 | 1) 发起外包计算任务；2) 用秘密共享将输入 X 分发给服务器；3) 生成公开参数 pp 和函数承诺 C；4) 支付押金到智能合约 | **不完全可信**——可能拒绝支付报酬 |
| **Server（服务器）** | 任务执行方 | 1) 从任务池选择子任务；2) 签名并支付押金；3) 执行计算得 y_i = F(x_i)；4) 生成证明 ω_i = g^{q_i(τ)}；5) 将证明打包成 DAG 交易上链 | **不完全可信**——可能提交错误结果骗取奖励 |
| **Verifier（验证者）** | 验证执行方 | 1) 从 DAG 账簿中提取同任务的所有证明；2) 聚合证明并执行批量验证；3) 触发奖惩：诚实者获得奖励+退还押金，恶意者没收押金 | **诚实但好奇（Honest-but-Curious）**——诚实执行验证但可能试图从证明中推断额外信息 |

## 3.5 安全/威胁模型

### 攻击者能力假设

| 攻击者类型 | 能力 | 目标 | 防御机制 |
|-----------|------|------|---------|
| **恶意用户 (Malicious User)** | 发起任务、接收正确结果 | 拒绝支付报酬（搭便车） | 押金机制——用户也需抵押，不良行为被罚没 |
| **恶意服务器 (Malicious Server)** | 选择任务、执行计算、生成证明 | 提交错误结果骗取奖励；将明文结果上链泄露隐私 | 验证机制检测错误结果；仅证明上链，结果链下存储 |
| **诚实但好奇的验证者 (H-B-C Verifier)** | 诚实执行验证协议、从证明中推断信息 | 从证明 ω_i 和承诺 C 中推断计算结果 y_i | ω_i = g^{q_i(τ)} 基于 ECDLP，验证者无法从群元素反推输入 |

### 信任边界

```
  信任域内                       不信任域
  ┌─────────┐                 ┌─────────────┐
  │  用户    │                 │  服务器      │
  │ (部分可信)│                │  (不可信)    │
  └─────────┘                 └──────┬──────┘
       │                             │
       └──────────┬──────────────────┘
                  │
          ┌───────┴───────┐
          │  Blockchain   │  ← 信任锚点 (Trust Anchor)
          │  + Verifiers  │    去中心化可信计算基
          │               │    (H-B-C，不主动作恶)
          └───────────────┘
```

### 安全目标

1. **公平性（Fairness）**：
   - 任务分配公平：任何算力级别的服务器都能获得子任务
   - 支付公平：恶意用户无法免费使用计算资源，恶意服务器无法骗取报酬

2. **安全性（Security / Confidentiality）**：
   - 秘密输入 X 在传输和计算过程中不泄露（基于秘密共享的门限安全）
   - 计算结果 y_i 不直接暴露在链上（依靠 ECDLP 困难性）

3. **可验证性（Verifiability）**：
   - 验证者可以通过聚合证明准确判断所有子任务计算结果的正确性
   - 恶意服务器无法伪造能通过验证的证明（基于多项式整除性约束）

4. **可扩展性（Scalability）**：
   - DAG 账本结构支持多队列并行出块，消除孤块浪费
   - 交易确认时间显著低于传统链式区块链

### 密码学假设

- **ECDLP 假设**（椭圆曲线离散对数问题困难）：在双线性群 G 中，给定 g^a，计算 a 是计算上不可行的。这是证明 ω_i 安全的底层假设。
- **秘密共享安全性**：少于 t 个份额无法恢复秘密 X（Shamir 秘密共享的经典性质，多项式次数为 t-1）。
- **双线性配对（Bilinear Pairing）**：存在高效可计算的双线性映射 e: G₁ × G₂ → G_T。
