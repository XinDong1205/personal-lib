## 3.2 参与实体与角色

| 实体 | 角色与职责 | 信任假设 |
|------|-----------|---------|
| **TA（Trusted Authority，可信权威）** | 系统初始化（选择椭圆曲线参数、生成系统密钥 $SK_{TA}$）、车辆和 RSU 的注册与凭证签发、恶意消息发送者的真实身份追溯、车辆伪身份更新服务 | **完全可信**——TA 掌握所有实体的注册信息，是系统中唯一的信任锚点 |
| **RSU（Roadside Unit，路侧单元）** | 首次认证：验证车辆身份、协商会话密钥、向区块链写入认证凭证；切换认证：读取区块链上的凭证、验证车辆身份、广播车辆提交的事故报告；内部集成 PUF 硬件模块 | **半可信（semi-trusted）**——RSU 可能被物理俘获，但 PUF 保护使其内部秘密不会泄露 |
| **OBU/车辆（On-Board Unit）** | 发起首次认证、切换认证请求、V2V 广播（无 RSU 场景）；车辆端通过驾驶员生物特征保护本地密钥材料；持有伪身份 $PID_i$ 作为网络层身份标识 | **不可信**——可能为恶意内部用户，可能被侧信道攻击入侵 |
| **区块链（Blockchain）** | 作为 RSU 之间共享认证凭证的不可篡改媒介；每个认证记录包含 RSU 的签名，其他 RSU 可独立验证其真实性和完整性 | **公开但不可篡改**——内容对攻击者可见，但无法被修改 |

## 3.3 模块划分与分工

```
┌────────────────────────────────────────────────────────────┐
│                      协议模块架构                            │
├──────────────┬──────────────┬──────────────┬────────────────┤
│  初始化模块   │  注册模块     │  认证模块     │  身份管理模块   │
│              │              │              │                │
│ • EC 参数选择 │ • 车辆注册   │ • 首次认证   │ • 伪身份更新   │
│ • 密钥生成    │ • RSU 注册   │ • 切换认证   │ • 生物特征绑定  │
│ • 系统参数发布 │ • PUF 挑战值 │ • V2V 广播   │ • 匿名追溯策略  │
│              │  生成        │  认证        │                │
└──────────────┴──────────────┴──────────────┴────────────────┘
```

- **初始化模块（Initialization）**：TA 选择安全椭圆曲线 $E(GF_q)$、生成系统公私钥对 $(SK_{TA}, PK_{TA})$、发布基点 $P$
- **注册模块（Registration）**：处理车辆和 RSU 的身份注册，TA 为每个实体生成唯一的密钥材料。车辆端额外执行生物特征绑定（fuzzy extractor）；RSU 端额外执行 PUF 绑定
- **认证模块（Authentication）**：核心模块，包含三个子阶段——首次认证（First Authentication）、V2I 切换认证与公告（Handover Authentication and Announcement）、V2V 消息广播（V2V Message Broadcast）
- **身份管理模块（Identity Management）**：支持车辆请求 TA 更新伪身份，使用旧伪身份对应的随机数 $r_i$ 作为对称加密密钥保护更新消息

## 3.5 安全/威胁模型

### 3.5.1 攻击者能力假设（基于 Dolev-Yao 模型扩展）

本文采用 Dolev-Yao（DY）模型 [25] 结合 VANET 实际场景定义攻击模型：

1. **内部攻击者**：攻击者 $\mathcal{A}$ 可以是合法注册的车辆（或内部人员），可以从系统内部发起冒充攻击或发布恶意消息
2. **信道完全控制**：$\mathcal{A}$ 可以窃听、修改、拦截和重放所有通过公开信道传输的消息
3. **侧信道攻击**：$\mathcal{A}$ 可以对 OBU 和 RSU 发起侧信道攻击（如功耗分析、时序分析）以获取存储数据，但**无法提取生物特征密钥**（假设生物特征有足够熵）且**无法破解 PUF**（物理探测会改变 PUF 响应）
4. **区块链公开可见但不可修改**：$\mathcal{A}$ 可以读取区块链上的所有内容，但无法篡改已写入的数据（假设底层共识机制安全）

### 3.5.2 信任边界

```
┌─── 完全可信域 ───┐
│       TA          │
└──────────────────┘
        │
        │ 签发凭证
        ▼
┌─── 半可信域 ──────────────────────────┐
│  RSU (PUF 保护秘密, 物理暴露)          │
│  - 正常运行时可信                     │
│  - 被俘获后秘密仍受 PUF 保护           │
└──────────────────────────────────────┘
        │
        │ 相互认证
        ▼
┌─── 不可信域 ──────────────────────────┐
│  OBU/车辆                             │
│  - 可能为恶意内部用户                  │
│  - 可能被侧信道攻击                    │
│  - 生物特征提供最后防线               │
└──────────────────────────────────────┘
        │
        │ 公开信道
        ▼
┌─── 攻击者域 ──────────────────────────┐
│  攻击者 A                             │
│  - Dolev-Yao 能力                     │
│  - 可物理俘获 RSU (但无法破解 PUF)     │
│  - 可侧信道攻击 OBU (但无法提取生物特征)│
└──────────────────────────────────────┘
```

### 3.5.3 安全目标（Design Goals）

| 目标 | 描述 |
|------|------|
| **相互认证** | 车辆与 RSU 之间、车辆与车辆之间的双向身份认证 |
| **会话密钥安全** | 每次会话生成独立的会话密钥 $SK_{ti}$，满足已知密钥安全（Known-Key Security）和完美前向保密（Perfect Forward Secrecy） |
| **条件隐私保护** | 伪身份不可链接（动态随机数 $r_i$），但 TA 可在必要时追溯 |
| **抗 RSU 俘获攻击** | 基于 PUF 物理特性保护 RSU 内部秘密 |
| **抗 OBU 入侵攻击** | 基于生物特征密钥保护 OBU 内部凭证 |
| **抗重放攻击** | 时间戳 + 随机数机制 |
| **抗伪造/冒充攻击** | 所有签名均绑定实体私钥和 TA 签发的凭证 |
| **抗去同步攻击** | 伪身份更新失败时仍可使用旧身份继续认证 |
