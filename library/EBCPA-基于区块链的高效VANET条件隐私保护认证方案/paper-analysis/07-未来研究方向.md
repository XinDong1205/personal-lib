# 7. 未来研究方向

## 7.1 论文提出的未来工作

作者在 Conclusion 部分明确指出了两个未来方向：

### 1. 专用区块链设计

> *"We will further improve the efficiency of EBCPA via designing a specified blockchain (e.g., novel architecture, data structure, or consensus mechanism)."*

**解读**：当前 EBCPA 使用通用区块链平台（Ethereum/Hyperledger），继承了其通用设计的效率限制。设计面向 VANETs 认证场景的专用区块链，可能从以下方面入手：
- **数据结构**：为匿名公钥的快速检索设计专门的索引结构（替代通用 key-value mapping）
- **共识机制**：利用 VANETs 中 RSU 的地理分布和信任假设，设计轻量级共识（如基于地理位置的 BFT 变体）
- **分片/分层**：按地理区域分片，减少每笔交易需要的共识节点数

### 2. 真实世界部署与评估

> *"We will evaluate our prototype based on a hybrid hardware and software implementation in the real-world VANETs."*

**解读**：当前评估完全基于仿真环境（VanetMobiSim + NS-2），作者承认"真实环境下的效果仍不确定"。真实世界部署面临仿真中未体现的挑战，如：
- 无线信道的多径衰落和干扰
- OBU 硬件性能的异构性
- 真实交通模式的不确定性

## 7.2 潜在的扩展方向

### 方向 1：去中心化 Manager（门限化追溯密钥）

当前方案的集中式 Manager 是最大的单点信任风险。一个自然的改进方向是使用**门限密码学**（Threshold Cryptography）将 `lskm` 分散到多个 Manager 节点：

- `(t, n)` 门限方案：追溯需要至少 `t` 个 Manager 节点协作
- 每个 Manager 节点持有 `lskm` 的一个份额 `lskm_i`
- 追溯时采用分布式计算：`LPK = APK2 - (∑ λ_i · lskm_i) · APK1`（其中 `λ_i` 为 Lagrange 系数）

这消除了单点攻破的风险，但引入了额外的通信开销（追溯需要多方参与）。

### 方向 2：跨域互操作性

在真实部署中，不同城市/国家可能由不同的 Manager 管理。跨域场景需要：
- **跨域匿名认证**：车辆使用 A 域 Manager 授权的匿名公钥能否在 B 域被接受？
- **跨域追溯**：B 域的 Manager 如何请求 A 域 Manager 协助追溯？
- **跨域密钥派生**：车辆进入 B 域后，是否需要向 B 域的 Manager 注册新的根匿名公钥？

可能的解决方案包括使用**分层密钥派生**（Hierarchical KeyDer）或**跨链通信协议**。

### 方向 3：提高通信效率

EBCPA 的签名/公钥总大小为 392 bytes，有压缩空间：

- **签名压缩**：通过优化 SoK 结构，将 `(c, z1, z2, R1, R2)` 压缩为 3 个群元素（如采用 Short Separable Signatures 的技术）
- **公钥压缩**：使用椭圆曲线点的压缩表示（x 坐标 + 1 bit 符号位），将每个点从 64 bytes 降至 33 bytes
- **批量通信优化**：在批量验证场景中，可以共享某些公共参数（如 `LPKm`）

### 方向 4：抗量子攻击版本

当前方案的安全性基于椭圆曲线离散对数问题（ECDLP），在 Shor 算法的量子攻击下不安全。后量子迁移可考虑：

- **基于格的 SoK**：将 SoK 从离散对数关系迁移到格上的 SIS/LWE 关系
- **基于哈希的密钥派生**：KeyDer 本身基于哈希链，迁移成本相对较低
- **混合方案**：在过渡期内同时支持 ECDLP-based 和 Lattice-based 两种模式

### 方向 5：形式化安全分析的完善

当前论文仅对匿名性给出了形式化定义和证明。以下安全属性的形式化建模是重要的理论工作：

- **可追溯性的形式化定义**：通常定义为 Manager 能从任意有效匿名公钥唯一恢复真实公钥，且任何非 Manager 方无法做到
- **不可链接性的形式化定义**：通过链接游戏（Linkability Game）定义
- **UC（Universal Composability）框架下的安全性**：将 EBCPA 建模为 UC 框架中的理想功能，获得可组合的安全保证

### 方向 6：高效的撤销传播机制

当前方案中，当 Manager 调用 `Revoke()` 后，其他车辆只能在下次调用 `Check()` 时发现公钥已撤销。如果车辆在两次 Check 之间持有了一个已撤销公钥签名的消息，存在时间窗口攻击（Window-of-Vulnerability）。改进方向：

- **撤销列表的主动推送**：RSU 定期广播撤销列表（CRL 的区块链版本）
- **短生命周期的匿名公钥**：进一步缩短公钥的有效期，减少撤销延迟的影响
- **基于累加器的撤销**：使用密码学累加器（如 RSA Accumulator）实现 `O(1)` 大小的撤销证明

### 方向 7：激励机制设计

当前方案假设车辆自愿参与协议，未讨论激励机制。在实际部署中：
- 车辆为什么愿意共享交通信息（消耗带宽和算力）？
- 车辆为什么愿意向 Manager 注册？
- RSU 维护区块链全节点的成本谁来支付？

基于区块链的代币激励机制（如信息质量越高、奖励越高）可以与 EBCPA 的认证框架结合。

## 7.3 相关工作延伸阅读

以下是 5 篇与 EBCPA 紧密相关的推荐阅读：

### 1. Lin et al., "BCPPA: A Blockchain-based Conditional Privacy-Preserving Authentication Protocol for Vehicular Ad Hoc Networks"
*IEEE Transactions on Intelligent Transportation Systems, 2021*

EBCPA 的直接前作。理解 BCPPA 的设计和不足是理解 EBCPA 创新的最佳途径。重点关注其追溯机制的线性复杂度来源，以及 EBCPA 如何通过代数结构改造将 `O(k)` 降为 `O(1)`。

### 2. Gutoski & Stebila, "Hierarchical Deterministic Bitcoin Wallets that Tolerate Key Leakage"
*FC 2015*

EBCPA 的 KeyDer 方案的密码学基础。该论文形式化分析了 BIP32 类分层确定性钱包在密钥泄露场景下的安全性，提供了 EBCPA 密钥派生安全分析的理论框架。

### 3. Chase & Lysyanskaya, "On Signatures of Knowledge"
*CRYPTO 2006*

知识签名（SoK）的定义性工作。EBCPA 的 SoK 构造遵循了该论文的范式（Σ-协议 + Fiat-Shamir 启发式），阅读该工作有助于理解 SoK 的形式化安全模型和更高效的构造方法。

### 4. Feng et al., "BPAS: Blockchain-Assisted Privacy-Preserving Authentication System for Vehicular Ad Hoc Networks"
*IEEE Transactions on Industrial Informatics, 2020*

EBCPA 的主要对比方案之一。BPAS 采用属性基加密（ABE）路径实现隐私保护认证，与 EBCPA 的 SoK 路径形成对比，有助于理解两种密码学路径在 VANETs 场景中的优劣。

### 5. Lu et al., "A Blockchain-Based Privacy-Preserving Authentication Scheme for VANETs"
*IEEE Transactions on Very Large Scale Integration Systems, 2019*

较早的区块链 + VANETs 认证工作，采用了 Merkle Patricia Tree 的数据结构。理解该工作的多轮交互问题，有助于理解 EBCPA 为何强调"一次交互、无限派生"的设计目标。
