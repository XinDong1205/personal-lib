# 1. 核心研究目标

## 1.1 核心问题（一句话概括）

在车联网（IoV）环境下，现有基于区块链的数据共享方案面临**系统吞吐量低**和**共识速度慢**两大瓶颈，且缺乏对恶意节点攻击（Sybil 攻击、合谋攻击、Eclipse 攻击）的有效防御机制。

## 1.2 问题的重要性

车联网场景具有**高移动性、大规模节点、实时性要求强**三大特征。车辆持续产生海量数据（交通流量、路况信息、事故报告等），这些数据的共享需要同时保证：

- **安全性**：数据不被篡改、不被恶意节点伪造
- **隐私性**：车辆身份和数据内容的隐私保护
- **实时性**：数据验证和共识达成必须足够快，否则失去时效价值
- **可扩展性**：系统必须能容纳大量节点的加入与退出

如果不解决吞吐量和共识延迟问题：
- 区块链系统将成为整个 IoV 数据管道的性能瓶颈，数据积压导致交通决策滞后
- 恶意节点可轻易通过自由加入网络发起攻击，影响数据可信度
- 传统 PBFT 的 $O(n^2)$ 通信复杂度使其无法规模化部署

## 1.3 论文的主要贡献

论文明确列出了三项贡献：

### 贡献 1：提出了一种基于分片区块链的数据共享方案
> "We propose a sharded blockchain-based data sharing scheme, enhancing data security and reliability."

**解读**：将网络按地理位置和节点属性划分为多个独立并行的共识分片（shard），每个分片内部自行处理交易和共识。相比传统单链方案将所有交易广播到全网节点，分片架构实现了水平扩展——分片数量越多，系统整体吞吐量越高。

### 贡献 2：提出了区块链分片协议与代理节点选择算法
> "We propose a blockchain sharding protocol and a proxy node selection algorithm, reducing risks associated with malicious nodes and improving overall system security."

**解读**：设计了一套基于**共识分数（Consensus Score, CS）**的节点评估机制，综合考量节点的声誉（Reputation Score）、计算能力（Computing Power）和位置中心性（Location Centrality），并利用深度强化学习（DRL）动态决定分片数量和代理节点阈值。这确保只有高信任度的节点才能成为代理节点（Proxy Node），降低了分片被恶意节点控制的概率。

### 贡献 3：引入 BLS-PBFT 共识算法
> "We introduce a BLS-PBFT consensus algorithm for IoV scenarios that improves transaction verification efficiency, reduces communication overhead, and increases Sybil attack [resistance]."

**解读**：将 Boneh-Lynn-Shacham (BLS) 签名聚合技术嵌入 PBFT 共识流程，将传统 PBFT 的 Prepare 和 Commit 阶段的 $O(n^2)$ 通信复杂度降低至 $O(n)$。BLS 短签名的特性不仅减少了单条消息的体积，其聚合特性更允许代理节点将多个验证者的签名聚合为单一签名，大幅减少广播消息数量。
