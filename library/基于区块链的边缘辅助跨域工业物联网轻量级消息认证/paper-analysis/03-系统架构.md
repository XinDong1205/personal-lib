## 3.2 参与实体与角色

| 实体 | 英文缩写 | 所属层 | 职责 |
|------|----------|--------|------|
| 智能设备 | SD | 终端设备层 | 数据感知与处理；协商服务密钥；签名和加密消息；解密和验证消息。**计算/通信/移动能力受限，身份需匿名** |
| 可信权威 | TA | 管理层 | 系统初始化（生成主密钥 `msk`）；为域内 SD 生成假名 `PID` 和密钥对；管理 IIoT 服务；**唯一可追溯消息来源的实体** |
| 边缘服务器 | ES | 管理层 | 存储和转发消息；辅助 SD 生成服务密钥；查询区块链获取信息。**作为中继节点，无需匿名** |
| 区块链域代理 | BCDA | 管理层 / 区块链层 | 各域有一个 BCDA，共同组成联盟区块链；协商并部署智能合约；与 TA 协作更新设备信息、撤销非法设备 |

## 3.3 模块划分与分工

系统可分为以下功能模块：

```
模块 1: 系统初始化模块 (Setup)
  - 执行方: TA
  - 功能: 生成各域的系统参数 (params, msk, P_pub) 和 ES 密钥对
  - 输出: 公共参数发布到 IIoT；ES 密钥对安全分发给 ES

模块 2: 设备注册模块
  - 执行方: TA
  - 功能: 为新 SD 生成多组 (sk_i,j, PK_i,j, PID_i,j, VP_i,j)，周期性更新
  - 输出: 通过安全信道分发给 SD；将初始参数写入区块链

模块 3: 服务密钥协商模块 (SBKGen)
  - 执行方: ES_A + ES_B + SD^B_head (头设备)
  - 功能: 为某个特定义务 serv_t 协商加密密钥 PK_serv_t 和解密密钥 sk_serv_t
  - 输出: PK_serv_t 分发给域 A 的发送方；sk_serv_t 分发给域 B 的接收方群组

模块 4: 消息签名与加密模块 (Sign + Encrypt)
  - 执行方: SD^A_i (发送方)
  - 功能: 对明文 m 签名得到 σ，再加密得到密文 c
  - 输出: δ = (c, W, PID^A_i,j, Ti) 发送到 ES_A

模块 5: 消息解密与验证模块 (Decrypt + Verify)
  - 执行方: SD^B_k (接收方)
  - 功能: 解密得到 m' 和 σ'，验证签名合法性
  - 辅助: ES_B 查询区块链确认 PID 有效性并获取对应公钥
  - 输出: 验证通过则接受，否则丢弃

模块 6: 非法消息追溯与身份撤销模块
  - 执行方: TA_X + BCDA_X
  - 功能: 从非法消息中提取 RID；停止生成新假名；通过智能合约从区块链删除
```

## 3.4 整体交互流程

### 阶段一：系统初始化

```
TA_A                                TA_B (及其他域 TA)
 │                                    │
 ├─ 协商安全哈希函数 H1~H5 ──────────┤
 ├─ 生成 msk_A, P^A_pub             ├─ 生成 msk_B, P^B_pub
 ├─ 生成 ES_A 密钥对 (sk^A_ES, PK^A_ES)  ├─ 生成 ES_B 密钥对
 ├─ 为域内 SD 批量生成假名和密钥 ────┤─ 同上
 ├─ 将 {P^A_pub, PK^A_ES} → BCDA_A │─ 将 {P^B_pub, PK^B_ES} → BCDA_B
 │                                    │
 ▼                                    ▼
[区块链] 写入智能合约, 初始化 Listserv
```

### 阶段二：服务密钥协商（以服务 serv_t 为例）

```
SD_A_i → ESA: (准备发送消息)
                      ESA → ESB: Sig_{sk^A_ES}(serv_t)  [请求协商]
                                       ESB → SD^B_head: serv_t
                                                  SD^B_head:
                                                    选随机数 d ∈ Z*_q
                                                    PK_serv_t = d·P
                                                    sk_serv_t = d + sk^B_head · h
                                       SD^B_head → ESB: PK_serv_t
                                       SD^B_head → 其他SD_B: {sk_serv_t, PK_serv_t} [安全信道]
                      ESB → ESA: Sig_{sk^B_ES}(PK_serv_t, PK^B_head)
                      ESA → TAA: Sig_{sk^A_ES}(ID^B_ES, PK^B_ES, PK_serv_t, PK^B_head)
                      ESA → SD_A_i: 同上
TAA → BCDAA: Sig_{msk_A}(Store_req, serv_t, PIDS, SDPKS, VPS)
                                       BCDAA → 区块链: 写入 Listserv_t
```

### 阶段三：消息签名、加密、发送

```
SD^A_i (发送方):
  1. 选随机数 w, u ∈ Z*_q
  2. W = w·P, U = u·P
  3. h3 = H3(PID^A_i,j, W, U)
  4. h = H3(ID^B_ES, PK^B_ES, PK^A_ES)
  5. σ = sk^A_i,j · (H5(m)·w + (h+h3)·u)^{-1}
  6. s = H4(U, Ti) ⊕ (m || σ)
  7. Y^A_i = u · (PK_serv_t + h · PK^B_head)
  8. c = (s, Y^A_i)
  9. 发送 δ = (c, W, PID^A_i,j, Ti) → ESA → ESB
```

### 阶段四：消息解密、验证

```
ESB 收到 δ' = (c', W', PID^A'_i,j, T'_i):
  ├─ 查询区块链: PID^A'_i,j 是否在 Listserv_t 中且未过期?
  │   ├─ 否 → 直接丢弃
  │   └─ 是 → 获取 PK^A'_i,j 并转发 δ' 和 PK^A'_i,j 给 SD^B_k

SD^B_k 收到 δ':
  1. 检查 T'_i 是否过期: 若当前时间 T - T'_i ≥ ΔT → 丢弃
  2. U' = Y^A'_i · sk^{-1}_serv_t
  3. m' || σ' = H4(U', T_i) ⊕ s'
  4. h'_3 = H3(PID^A'_i,j, W', U')
  5. h = H3(ID^B_ES, PK^B_ES, PK^A_ES)
  6. 验证: PK^A'_i,j ?= σ' · (H5(m')·W' + (h + h'_3)·U')
      ├─ 成立 → 接受
      └─ 不成立 → 丢弃
```

## 3.5 安全/威胁模型

### 攻击者能力假设

论文将攻击者分为两类：

| 类型 | 目标 | 安全定义 | 密码学假设 |
|------|------|----------|------------|
| $\mathcal{A}_I$ | 破坏消息机密性 | IND-CCA2 | ECDHP (椭圆曲线 Diffie-Hellman 问题) |
| $\mathcal{A}_{II}$ | 破坏消息不可伪造性 | EUF-CMA | ECDLP (椭圆曲线离散对数问题) |

两类攻击者均在**随机谕言机模型（Random Oracle Model）**下分析，即哈希函数被建模为理想的随机谕言机。

### 攻击者能力（以 IND-CCA2 游戏为例）

$\mathcal{A}_I$ 在游戏中可以：
- 查询所有 5 个哈希谕言机（H1 ~ H5）
- 提取任意服务的加密/解密/验证/签名密钥
- 替换加密密钥
- 对任意消息执行加密/解密查询

但在 Challenge 阶段**不能查询挑战密文对应的解密密钥或解密结果**（IND-CCA2 标准约束）。

### 信任边界

```
[可信] 各域 TA ── 仅被域内实体信任
[半可信] 各域 ES ── 诚实但可能好奇（honest-but-curious），中继消息但不需匿名
[不可信] SD ── 跨域的其他 SD 不可信
[可信] 区块链 ── 防篡改共享账本，数据存储可信
[恶意] 网络攻击者 ── 可拦截、修改、重放网络消息
```

### 安全目标（7 项）

1. **消息机密性**：只有合法接收方能解密消息
2. **消息完整性与认证**：接收方能验证消息未被篡改
3. **消息匿名性**：除同域 TA 外无人能获得设备真实身份
4. **不可链接性**：同一设备发出的两条消息不可被关联
5. **可追溯性**：发现非法消息时，TA 可追溯到发送设备
6. **身份撤销**：TA 可撤销非法设备的身份
7. **抗常见攻击**：重放攻击、修改攻击、冒充攻击
