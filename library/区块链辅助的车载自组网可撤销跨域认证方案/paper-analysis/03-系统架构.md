## 3.2 参与实体与角色

| 实体 | 所属层 | 职责 |
|---|---|---|
| **OAS**（Original Domain Authentication Server，原域认证服务器） | 管理域层 | 域的密钥管理与身份管理；可以是 CA、TA 或 KGC 等不同形式。在域内被视为可信，但**与其他域 OAS 之间不完全互信**（存在合谋风险）。 |
| **Vehicle**（车辆） | 管理域层 | 装备 OBU（通信）和 TPD（安全存储/计算）。在归属域已完成注册认证，跨域时需获得访问域的许可证。车辆本身被视为**不可信实体**。 |
| **RSU**（Roadside Unit，路侧单元） | 联盟链层（域内） | 组成域内的联盟区块链，维护非法车辆列表（Illegal_list），为车辆提供智能合约调用 API。**假设不会提供错误的 API**。 |
| **DS**（Dedicated Server，专用服务器） | 联盟链层（跨域） | 每个域的 OAS 选择一个 DS。所有域的 DS 组成跨域联盟区块链，存储域公钥和车辆跨域注册信息，为 OAS 提供智能合约调用 API。 |

### 信任假设总结

- OAS 在**域内**完全可信
- OAS **域间**不完全互信（可能合谋以泄露车辆隐私）
- RSU 提供正确的 API 但不一定是完全可信（合谋需要控制超过半数节点）
- DS 同理，需要控制超过半数节点才能篡改
- 车辆完全不可信
- 攻击者模型遵循 **Dolev-Yao 威胁模型**（可监听、篡改、重放、冒充消息）

## 3.3 模块划分与分工

```
┌─────────────────────────────────────────────────────┐
│                  系统功能模块                          │
├─────────────┬───────────────┬───────────────────────┤
│ 系统初始化   │ 域内认证模块   │ 跨域认证模块            │
│ (Sec IV-A)  │ (Sec IV-B)    │ (Sec IV-C)            │
├─────────────┼───────────────┼───────────────────────┤
│• 公共参数协商 │• 保留现有方案  │• 跨域预认证 (CDPAP)    │
│• 密钥对生成  │• 无需修改      │• 跨域通信 (CDCP)       │
│• 域标识上链  │               │• 身份追踪              │
│             │               │• 身份撤销与密钥更新     │
└─────────────┴───────────────┴───────────────────────┘
```

| 模块 | 功能 |
|---|---|
| **系统初始化** | 各域预协商椭圆曲线、双线性映射等公共参数；OAS 生成 APK、U、X、Y 等密钥对；上传域标识 GID 和公钥到 DS 联盟链。 |
| **域内认证** | 完全保留各域原有的认证方案（证书、IBC、群签名等），不做任何改动。这是本方案区别于其他方案的关键设计点。 |
| **跨域预认证（CDPAP）** | 车辆通过归属域 OAS 作为中介，与访问域 OAS 进行一轮交互，获得访问域的许可证（License）和多项式片段。 |
| **跨域通信（CDCP）** | 车辆使用许可证自生成一次性匿名签名，访问域内实体独立验证签名，无需第三方辅助。 |
| **身份追踪** | 访问域 OAS 利用主密钥从匿名签名中提取车辆跨域公钥，再联合归属域 OAS 获得真实身份。 |
| **身份撤销** | 通过双变量多项式广播更新消息，合法车辆自主更新许可证，被撤销车辆因多项式值为零而无法计算更新秘密。 |

### 流程说明

**阶段③ 跨域预认证**（论文 Fig. 3 详细描述，共 5 步）：

1. 车辆选择随机私钥 vsk，计算公钥 vpk，用对称密钥加密目标域信息，发送 M1。
2. 归属域 OAS_A 解密、验证签名，计算跨域身份 CID，用访问域公钥加密并签名，发送 M2。
3. 访问域 OAS_B 解密、验证，生成许可证 Lic（基于 P-S 签名）和双变量多项式 fi(x,y)，加密发送 M3，同时调用 Algorithm 1 将车辆公钥注册到 DS 区块链。
4. 归属域 OAS_A 解密、验证，查询区块链确认注册，计算多项式片段 gi(y)，加密发送 M4。
5. 车辆解密获得许可证 Lic 和 gi(y)，存储于 TPD。

**阶段④ 跨域通信**（Algorithm 3 & 4）：

- 车辆选择随机数 ν, τ，随机化许可证为 I0, I1, I2（一次性签名），再选 tk, tv 计算辅助值和挑战值，生成 NIZK 证明。
- 接收方用 Algorithm 4 验证：（1）双线性配对验证签名有效性，（2）验证挑战值 ch 的一致性。

## 3.5 安全/威胁模型

### 攻击者能力假设（Dolev-Yao 模型 + 扩展）

| 攻击类型 | 攻击者能力 |
|---|---|
| **被动攻击** | 监听无线信道，获取所有传输消息 M1-M4、Mv |
| **主动攻击** | 篡改、重放、伪造消息 |
| **中间人攻击** | 在通信双方之间截获并修改消息 |
| **冒充攻击** | 冒充合法车辆或 OAS 发送消息 |
| **服务器合谋攻击** | 多个域的 OAS/DS 合谋，试图标记车辆访问记录、泄露车辆位置隐私 |
| **区块链攻击** | 攻击者需控制超过半数 DS 或 RSU 节点才能篡改链上数据 |

### 信任边界

```
  ┌─────────────┐           ┌─────────────┐
  │   域 A       │  不完全互信 │   域 B       │
  │  OAS_A 可信  │ ◄────────► │  OAS_B 可信  │
  │  (仅域内)    │  信任边界   │  (仅域内)    │
  └─────────────┘           └─────────────┘
         │                         │
         │       ┌─────────┐       │
         └──────►│ 联盟链   │◄──────┘
                 │ (分布式) │
                 └─────────┘
                  半可信（需 > 50% 节点合谋）
```

### 安全目标

1. **消息认证性与完整性**：基于 CDH + LRSW 假设，不可伪造。
2. **匿名性**：一次性签名不泄露车辆真实身份。
3. **不可链接性**：即使同一车辆多次通信，签名之间无关联性。
4. **可追踪性**：访问域 OAS 可用主私钥 ask_B 从签名中提取 vpk，联合归属域获得真实 ID。
5. **可撤销性**：通过群公钥更新实现选择性撤销（被撤销车辆无法计算新秘密值 d）。
