# 04. 核心技术原理深度拆解

## 4.1 匿名公钥结构设计

**目的**：在不暴露车辆真实公钥的前提下，为车辆提供可被验证（任何人可验证签名）且可被追踪（TA 可揭示真实身份）的匿名身份凭证。

**核心思想**：将车辆的真实公钥 `PKi` 用 ElGamal 加密思想进行"盲化"，同时嵌入两把"解密钥匙"——一把对所有人隐藏（用于匿名认证），一把仅 TA 可解（用于追踪）。

**详细机制**：

1. TA 为车辆 Vi 选择随机数 `uj ∈ Z_q*`
2. 计算匿名公钥的三个分量：
   - `C1 = uj·P` —— 盲化因子，相当于 ElGamal 加密中的随机数承诺
   - `C2 = uj·PKi + PKi = (uj + 1)·PKi` —— 对 PKi 的"自盲化"，与自己的公钥绑定
   - `C3 = uj·MPK + PKi` —— 用 TA 主公钥加密的 PKi，相当于 ElGamal 密文
3. 计算索引 `cid = H(C1 || C2)` —— 用作链上查询键

**数学模型**：

设车辆的长期私钥为 `ski`，公钥为 `PKi = ski·P`。TA 的主私钥为 `msk`，主公钥为 `MPK = msk·P`。

```
C1 = uj·P                                    (1)
C2 = uj·PKi + PKi = (uj + 1)·ski·P          (2)
C3 = uj·MPK + PKi = uj·msk·P + ski·P        (3)
```

**关系推导**：由 (1)(2) 可导出 `C2 = ski·C1 + ski·P = ski·(C1 + P)`，这是 SoK 方案中要证明的核心关系。

**追踪原理**：TA 使用私钥 msk 可从 C3 中恢复 PKi：
```
PKi = C3 - msk·C1 = (uj·msk·P + ski·P) - msk·(uj·P) = ski·P = PKi
```

**创新点分析**：

- **用单一结构双路复用**：同一组 (C1, C2, C3) 同时承载了"匿名认证"（通过 C1, C2）和"条件追踪"（通过 C1, C3）两个功能，避免了为追踪额外构造独立通道的复杂性；
- **追踪效率 O(1)**：TA 无需遍历任何列表，直接通过 `cid` 获取 (C1, C3) 后一次点乘+一次点减即完成追踪。这与 Lin et al. [12] 的 O(n) 追踪形成了鲜明对比；
- **无需安全信道分发**：匿名公钥通过区块链公开存储，车辆通过 Get 获取即可，这在 PKI 和 ID-based 方案中往往需要安全信道。

## 4.2 SoK（签名知识证明）协议

**目的**：允许车辆在不暴露私钥的情况下向任何验证者证明自己拥有与匿名公钥对应的私钥，同时对消息内容进行数字签名。

**核心思想**：将 Sigma 协议（典型的"知识证明"交互协议）通过 Fiat-Shamir 启发式变换为非交互式方案，并将其绑定到消息和时戳上实现签名功能。

### 4.2.1 协议详细机制

**SoK 协议证明的关系**：
```
R = { (xi = (C1, C2), wi = ski) : C2 = ski·C1 + ski·P }
```
即：证明方知道私钥 `ski` 满足 `C2 = ski·(C1 + P)`。

#### GenProof（签名生成）

**输入**：私钥 `ski`、公开信息 `xi = (C1, C2)`、消息 `msgi`、时戳 `ti`

**步骤**：
```
1. 选取随机数 ri ∈ Zq*
2. 计算承诺 Ri = ri·C1 + ri·P = ri·(C1 + P)
3. 计算挑战 ei = H(P, C1, C2, Ri, msgi, ti)
4. 计算响应 zi = ri - ei·ski  (mod q)
5. 输出签名 σi = {zi, Ri}
```

**关键观察**：步骤 2 中 `Ri` 的计算方式 `ri·(C1 + P)` 与证明关系 `C2 = ski·(C1 + P)` 的结构一致（都是用 `(C1 + P)` 作为基点进行标量乘）。这种"结构一致性"是验证等式成立的数学基础。

#### VerifyProof（单条验证）

**输入**：公开信息 `xi = (C1, C2)`、签名 `σi = {zi, Ri}`、消息 `msgi`、时戳 `ti`

**步骤**：
```
1. 解析 σi = {zi, Ri}
2. 计算 ei = H(P, C1, C2, Ri, msgi, ti)
3. 验证: Ri ?= zi·(C1 + P) + ei·C2
4. 等式成立 → 输出 1（有效），否则 → 输出 0（无效）
```

**正确性验证**：

```
zi·(C1 + P) + ei·C2
= (ri - ei·ski)·(C1 + P) + ei·(ski·C1 + ski·P)
= ri·(C1 + P) - ei·ski·(C1 + P) + ei·ski·(C1 + P)    [中间两项抵消]
= ri·(C1 + P)
= Ri  ✓
```

**关键安全设计**：
- 哈希输入中包含 `Ri` 和 `msgi`，使 Fiat-Shamir 变换绑定了消息认证（签名功能）和防重放（时戳绑定）；
- 如果从交互式 Sigma 协议来看：`Ri` 是承诺（Commitment）、`ei` 是挑战（Challenge）、`zi` 是响应（Response）；验证等式恰好复现了交互验证逻辑。

#### BVerifyProof（批量验证）

**输入**：n 条消息/签名对 `{(xi, msgi, σi, ti)}`，i = 1...n

**步骤**：
```
1. 对每条消息解析 σi = {zi, Ri}
2. 选取小随机向量 v = (v1, v2, ..., vn)，其中 vi ∈ [1, 2^t]，t 为小整数
3. 对每条消息计算 ei = H(P, C1, C2, Ri, msgi, ti)
4. 验证:
   Σ vi·Ri ?= Σ vi·zi·C1 + (Σ vi·zi)·P + Σ vi·ei·C2
5. 等式成立 → 输出 1，否则 → 输出 0
```

**正确性验证**：将单条验证等式两边各乘 vi 后累加：

```
Σ vi·Ri = Σ vi·[zi·(C1+ P) + ei·C2]
        = Σ vi·zi·C1 + Σ vi·zi·P + Σ vi·ei·C2
        = Σ vi·zi·C1 + (Σ vi·zi)·P + Σ vi·ei·C2  ✓
```

**小指数测试（Small Exponent Test）**：

向量 `v` 的作用是防止攻击者构造"批量验证通过但单条验证失败"的消息组合。若不引入随机性，攻击者可构造：
- `σ1` 有效：`R1 = z1·(C1+P) + e1·C2 + Δ`
- `σ2` "补偿"：`R2 = z2·(C1+P) + e2·C2 - Δ`
- 批量等式 `R1 + R2 = z1·(C1+P) + e1·C2 + z2·(C1+P) + e2·C2` 仍然成立（Δ 被抵消）

但引入随机 vi 后，`v1·Δ - v2·Δ ≠ 0`（概率意义上），使攻击者无法预先计算出补偿值。`t` 决定安全性——`vi` 的取值范围 `[1, 2^t]` 越大越安全，但乘法开销也越大。

### 4.2.2 安全性分析（NIZK 三性质）

#### 完备性（Completeness）

**命题**：诚实生成的证明一定通过验证。

**证明思路**：上述正确性验证等式已经给出了严格的代数推导。无论是单条验证 `Ri = zi·(C1+P) + ei·C2` 还是批量验证 `Σvi·Ri = Σvi·zi·C1 + (Σvi·zi)·P + Σvi·ei·C2`，等式均恒等成立。

#### 可靠性（Soundness）

**命题**：在 ECDLP 假设和随机谕言模型下，PPT 敌手无法构造不满足关系 `C2 = ski·(C1+P)` 的有效证明。

**证明思路（知识提取器构造与分叉引理）**：

1. 假设存在一个 PPT 证明者 `P*` 能以一个有效证明 `(σi = {zi, Ri})` 说服验证者
2. 构造知识提取器 `M`：
   - `M` 将 `P*` 回卷（rewind）到哈希查询 `H(P, C1, C2, Ri, msgi, ti)` 的时机
   - `M` 重新编程随机谕言，返回不同的挑战值 `e'i ≠ ei`
   - `P*` 产生第二个有效证明 `σ'i = {z'i, Ri}`（注意 Ri 不变，因为承诺基于同一 ri）
3. 由两条等式：
   ```
   Ri = zi·(C1 + P) + ei·C2
   Ri = z'i·(C1 + P) + e'i·C2
   ```
   相减得：`(zi - z'i)·(C1 + P) = (e'i - ei)·C2`
   
   利用 `C2 = ski·(C1 + P)` 代入：
   ```
   (zi - z'i) = (e'i - ei)·ski  (mod q)
   ski = (zi - z'i)·(e'i - ei)^{-1}  (mod q)
   ```

4. `M` 成功提取出 `ski`，从而解决了 ECDLP 实例（或证明了知识的存在）。若 ECDLP 困难，则这样的 `P*` 不存在。

**关键假设**：此证明依赖于随机谕言模型（哈希函数可被知识提取器"编程"）和分叉引理（提取器能回卷证明者到挑战前状态）。

#### 零知识性（Zero-Knowledge）

**命题**：存在一个模拟器 SIM 能在不知道私钥的情况下生成与真实证明不可区分的模拟证明。

**模拟器构造**（Algorithm 2）：

```
输入: 公开信息 xi = (C1, C2)
1. 随机选择 e*, z* ∈ Zq*
2. 计算 R* = z*·(C1 + P) + e*·C2
3. 编程随机谕言: H(P, C1, C2, R*, msgi, ti) = e*
输出: (msgi, σi = {z*, R*}, ti)
```

**不可区分性**：
- 真实证明中：`zi = ri - ei·ski`（均匀分布），`Ri = ri·(C1+P)`（由均匀随机的 ri 决定）
- 模拟证明中：`z*` 随机均匀选取（与 `zi` 同分布），`R*` 由 `z*` 和 `e*` 唯一确定（满足验证等式）
- 两者分布完全一致（在随机谕言模型下）

**为什么 Fiat-Shamir 变换的零知识性需要随机谕言？** 因为模拟器需要"编程"哈希函数的输出（将 `e*` 设为 H(...) 的输出），标准模型中哈希函数是确定性的，模拟器无法做到这一点。

### 4.2.3 SoK 中的创新点分析

1. **基点复用**：Sigma 协议的承诺计算 `ri·(C1+P)` 复用了匿名公钥的结构，使得签名长度仅为 `(zi, Ri)` = |Zq| + |G| ≈ 2 × 32 = 64 bytes（在 256-bit 曲线上），加上 cid 和时戳约 168 bytes；

2. **避免配对操作**：SoK 的验证等式只涉及椭圆曲线点乘和点加，完全不使用双线性配对——这是效率提升的根本原因。相比之下，许多基于双线性配对的方案中，单次配对操作约为 5–20 ms；

3. **消息绑定**：在 Fiat-Shamir 变换中，哈希输入包含 `msgi` 和 `ti`，使挑战值 `ei` 成为消息和时戳的函数，从而将 Sigma 协议（仅证明知识）升级为签名方案（同时认证消息和时效性）；

4. **与 Schnorr 签名的关系**：如果把 `(C1+P)` 视为"新的生成元"，SoK 方案实际上是一个在扩展基点上的 Schnorr 式签名。事实上，若 `C1 = O`（无穷远点），则该方案退化为标准 Schnorr 签名。论文的贡献在于将其适配到了匿名公钥的特定结构中。

## 4.3 智能合约设计

**目的**：以去中心化、不可篡改的方式管理匿名公钥的存储、查询和撤销，实现公开可验证性（任何人可独立获取验证所需公钥）的同时保留 TA 的管理权限。

**核心设计决策**：

### 数据结构
```
struct APK {
    uint256[2] C1;   // 256-bit 椭圆曲线点的 (x, y) 仿射坐标
    uint256[2] C2;
    uint256[2] C3;
}
mapping(uint256 => APK) apk;
```

使用 `uint256[2]` 而非 `bytes` 的原因是 Solidity 原生支持 256-bit 整数运算，直接用坐标分量存储避免了序列化/反序列化开销。缺点是无法在合约内做椭圆曲线运算验证（Ethereum 预编译合约在拜占庭分叉后支持 `ecAdd`/`ecMul`/`ecPairing`，但本文方案不需要链上运算）。

### 四个核心函数

| 函数 | 访问控制 | 功能 | Gas |
|------|---------|------|-----|
| Submit(cid, C1, C2, C3) | 仅 TA | 新增/更新匿名公钥 | ~$0.53 |
| Get(cid) | 公开 | 查询 C1, C2（用于签名验证） | 免费 |
| Trace(cid) | 仅 TA | 查询 C1, C3（用于身份追踪） | 免费 |
| Revoke(cid) | 仅 TA | 清空匿名公钥（撤销） | ~$0.14 |

### 设计要点

1. **Get 和 Trace 分离**：Get 返回 C1, C2（验证所需），Trace 返回 C1, C3（追踪所需）。C3 仅 TA 可见，防止攻击者利用 C3 进行离线追踪尝试；

2. **撤销即清空**：Revoke 将 C1, C2, C3 全部置为 NULL，后续 Get 将返回空值，使签名验证失败。这比维护额外的 CRL（证书撤销列表）简洁得多；

3. **部署经济性**：智能合约部署 Gas 约 $1.78，但仅执行一次。每次 Submit 约 $0.53（为每辆车每个认证周期支付一次），Revoke 约 $0.14。

## 4.4 完整密码学流程串联

将以上技术模块串联，完整的 EBCPPA 协议如下：

```
┌─ 系统初始化 ─────────────────────────────────────────────┐
│ TA: 选择群 (G, q, P), 哈希 H, msk ∈ Zq*, MPK = msk·P     │
│ TA: 部署智能合约 PKList, 自身成为 manager                  │
│ 发布: {G, q, P, H, MPK, scid}                             │
└───────────────────────────────────────────────────────────┘
                             │
┌─ 车辆注册 ───────────────────────────────────────────────┐
│ Vi: ski ∈ Zq*, PKi = ski·P                               │
│ Vi → TA (安全信道): RIDi, PKi                             │
│ TA: uj ∈ Zq*, C1=uj·P, C2=uj·PKi+PKi, C3=uj·MPK+PKi    │
│ TA: cid = H(C1||C2)                                       │
│ TA: Submit(cid, C1, C2, C3)  →  区块链                     │
│ TA → Vi: cid                                              │
└───────────────────────────────────────────────────────────┘
                             │
┌─ 消息签名（Vk 签名 msgk）─────────────────────────────────┐
│ Vk: Get(cid_k) → (C1, C2)                                 │
│ Vk: rk ∈ Zq*, Rk = rk·C1 + rk·P = rk·(C1+P)             │
│ Vk: ek = H(P, C1, C2, Rk, msgk, tk)                      │
│ Vk: zk = rk - ek·skk  (mod q)                             │
│ Vk → 广播: (cid_k, msgk, σk={zk, Rk}, tk)                 │
└───────────────────────────────────────────────────────────┘
                             │
┌─ 消息验证（验证方检查）───────────────────────────────────┐
│ 验证方: 检查 tk 鲜活性                                     │
│ 验证方: Get(cid_k) → (C1, C2)                             │
│ 验证方: ek = H(P, C1, C2, Rk, msgk, tk)                  │
│ 验证方: Rk ?= zk·(C1+P) + ek·C2                           │
│ 等式成立 → 接受消息; 否则 → 拒绝                            │
└───────────────────────────────────────────────────────────┘
                             │
┌─ 恶意行为追踪 ───────────────────────────────────────────┐
│ TA: Trace(cid_k) → (C1, C3)                               │
│ TA: PKk = C3 - msk·C1                                     │
│ TA: 查表 PKk → RIDk（车辆真实身份）                         │
│ TA: Revoke(cid_k) → 清空匿名公钥                           │
└───────────────────────────────────────────────────────────┘
```

### 密码学假设总结

| 安全目标 | 依赖的密码学假设/技术 |
|---------|---------------------|
| 签名不可伪造 | ECDLP + 随机谕言模型 + Fiat-Shamir 变换 |
| 身份匿名 | ElGamal 加密的 IND-CPA 安全性 + ECDLP |
| 条件可追踪 | ElGamal 解密正确性（信息论保证） |
| 不可链接性 | 随机数 uj 的均匀随机性（信息论保证） |
| 零知识（隐私保护） | Sigma 协议的 Honest-Verifier ZK + Fiat-Shamir 启发式 |
| 抗重放 | 时戳 ti 的新鲜性检查 |
| 抗篡改/冒充 | 签名不可伪造 → 蕴含消息认证和实体认证 |
| 数据不可篡改 | 区块链哈希链的安全性（抗碰撞哈希函数） |
